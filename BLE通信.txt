================================================================
BLE 通信（BLE HID）实现方案
================================================================
版本：V1.0
日期：2026-09-07
平台：nRF Connect SDK v3.2.3 / Zephyr 4.2.99 / 板卡 kb（nRF52840 / E73-2G4M08S1C）
依据：矩阵按键.txt、旋钮编码器.txt、模式切换.txt、蓝牙键盘方案.txt、原理图
      SCH_蓝牙小键盘_2026-03-28.pdf
范围：只描述「BLE 模式下与电脑通信」这一层
      1) 模式开关切到 BLE 档时，启动 BLE 广播并以 HID 设备角色与电脑配对/连接；
      2) 矩阵按键经 HID Keyboard Report 上报键值（含 NumLock 双层、修饰键）；
      3) EC11 旋钮经 HID Consumer Report 控制电脑系统音量（加减/静音）；
      4) 与模式切换、矩阵、旋钮、低功耗等既有模块对接，给出接入约定。
说明：本文件只给方案、协议设计、配置草案与验证方法，不含实现代码。

----------------------------------------------------------------
一、结论摘要
----------------------------------------------------------------
1. 本键盘在 BLE 模式下是一个标准「HID over GATT（HOGP）外设」：
   nRF52840 跑 Zephyr 蓝牙主机协议栈 + 片上 2.4G 射频，对电脑呈现为
   一个蓝牙键盘 + 消费控制设备（音量）。
2. 电脑侧（Windows/macOS/Linux/Android）无需装驱动，系统蓝牙直接识别为
   HID 键盘/多媒体设备；旋钮即系统音量控制。
3. 输入源与 USB 模式完全共用：矩阵按键（矩阵按键.txt）→ 标准键值事件，
   EC11 旋转（旋钮编码器.txt）→ 旋转事件，由 hid 层按当前模式决定发往
   USB 还是 BLE（本方案只描述 BLE 这一路）。
4. 模式门控来自模式切换.txt 的 kb_mode 模块：仅当 kb_mode_get()==KB_MODE_BLE
   时，键盘/音量报告才从 BLE HID 发出；切走时必须先发一次「全键释放」。
5. 对外接口沿用既有模块风格：固定大小回调数组 + 系统工作队列派发，
   不在中断/回调里阻塞，不写死 GPIO。

----------------------------------------------------------------
二、协议与硬件事实（方案依据）
----------------------------------------------------------------
2.1 采用的蓝牙规范
  - HID over GATT Profile（HOGP）：基于 Bluetooth SIG 的 HID Service
    （UUID 0x1812）+ Battery Service（0x180F，可选）+ Device Information
    Service（0x180A）。
  - 设备角色：Peripheral（外设），电脑是 Central（主机）。
  - 协议模式：HID 支持「Boot Protocol」与「Report Protocol」两种，电脑
    会通过 HID Control Point 选择；本方案键盘报告同时兼容两者。
  - 安全：HID 强制加密，必须配对（Pairing/Bonding）。本设备无屏幕/无输入
    数字能力，采用「Just Works」配对（手机/电脑弹「是否配对」即可），
    并启用 Bonding 把配对信息存到 Flash，便于重连。

2.2 两种 HID 报告
  (A) Keyboard Report（键盘报告）
      - Usage Page 0x01（Generic Desktop）→ 实际走 USB HID Usage Page 0x07
        （Keyboard/Keypad）的用法（usage）。
      - 报文长度 8 字节：1 字节修饰键 + 1 字节保留 + 6 字节键值（最多 6 键同报）。
      - 修饰键位：bit0=LCtrl,1=LShift,2=LAlt,3=LGUI,4=RCtrl,5=RShift,6=RAlt,7=RGUI。
      - 6 键滚动（6KRO）；本键盘 17 键小规模，6KRO 已足够，且矩阵带隔离二极管
        支持任意多键同按，仅受 6 字节报文容量限制。
  (B) Consumer Report（消费控制报告）
      - Usage Page 0x0C（Consumer），Usage = Consumer Control（0x01）。
      - 用于系统音量：Volume Increment（0xE9）、Volume Decrement（0xEA）、
        Mute（0xE2）。
      - 报文为 1~2 字节的 16 位用法值（其余位填充）。旋钮加减、编码器按键
        （Mute）走这一路。

2.3 与既有模块的引脚/资源关系
  - 射频由 nRF52840 片上 2.4G 提供，不占用任何 GPIO；
    与矩阵（ROW0~5/COL0~3）、旋钮 A/B（P0.10/P1.06）、MODE（P0.29）、
    WS2812（SPI2）、SAADC 互不冲突。
  - BLE 协议栈需要一定的 RAM/Flash（NCS 默认配置即可），后续若 Flash 紧张
    再裁剪日志/未用功能。

----------------------------------------------------------------
三、总体架构与数据流
----------------------------------------------------------------
3.1 模块划分（沿用 蓝牙键盘方案.txt 3.2 的命名）
  - ble_hid：本方案核心，BLE HID 服务初始化、连接管理、报告发送；
  - 它「消费」来自矩阵的按键事件和来自旋钮的旋转事件，在 mode==BLE 时
    产出 BLE HID 报告；
  - 与 mode 模块、keys 模块、knob 模块、led/display/power 通过事件/回调解耦。

3.2 数据流
  [物理矩阵] --(矩阵按键.txt 的 gpio-kbd-matrix + keymap)--> INPUT_EV_KEY 事件
        │   (应用层 INPUT_CALLBACK_DEFINE 或 CAF button_event)
        ▼
  [hid 路由层 hid_bridge]  读取 kb_mode_get()
        ├─ == KB_MODE_BLE  → 交给 ble_hid 组包发送
        └─ 其它模式        → （本方案不涉及，USB/2.4G 由各自模块处理）
        │
        ▼
  [ble_hid]  维护「当前按下键集合」与 NumLock 状态
        ├─ 按键变化 → 组 8 字节 Keyboard Report → bt_hids_inp_rep_send()
        └─ 旋钮事件 → 组 Consumer Report（音量加减/静音）→ bt_hids_inp_rep_send()

  [EC11 旋转] --(旋钮编码器.txt 的 knob 模块，每格回调)--> 旋转事件
        │
        ▼
  [ble_hid]  顺时针(CW)→Volume Inc；逆时针(CCW)→Volume Dec；
             编码器自身按键(ROW0/COL3, INPUT_KEY_MUTE)→Consumer Mute。

3.3 线程模型
  - 蓝牙协议栈运行在独立线程（Zephyr 蓝牙 Rx/Tx 线程），与业务线程解耦；
  - ble_hid 组包放在【系统工作队列】执行（与 led 动画、knob 派发同队列但
    独立工作项），回调里不阻塞、不调可能睡眠的 API；
  - 输入事件高频时若担心丢，可参考 矩阵按键.txt 5 节把
    CONFIG_INPUT_QUEUE_MAX_MSGS 调大（如 32）。

----------------------------------------------------------------
四、HID 报告设计（描述符要点）
----------------------------------------------------------------
4.1 Keyboard Report（Report ID = 1）
  报文布局（8 字节）：
      Byte0  修饰键位图（见 2.2A）
      Byte1  保留（0x00）
      Byte2~7 当前按下的 HID 用法 ID（最多 6 个，0 表示空）
  HID 描述符要点（仅列关键项，不贴完整字节）：
      - Usage Page (Generic Desktop), Usage (Keyboard)
      - Collection (Application)
          - Report ID (1)
          - 修饰键：8 个 Input 位（Bitmask，1 字节）
          - 保留 1 字节
          - 6 个 Input 字节（每个 = 1 个 Keycode，Array 类型）
          - Output Report 1 字节：LED（Num Lock 等），用于接收主机 NumLock 状态
      - End Collection
  （Boot Protocol 下 Zephyr bt_hids 会自动套用标准 8 字节 boot 键盘布局，
    无需另写描述符。）

4.2 Consumer Report（Report ID = 2）
  报文布局（2 字节，16 位用法值）：
      Byte0~1   Consumer 用法（见 2.2B）：0xE9 加音量 / 0xEA 减音量 / 0xE2 静音
  HID 描述符要点：
      - Usage Page (Consumer), Usage (Consumer Control)
      - Collection (Application)
          - Report ID (2)
          - 1 个 16 位 Input（Data, Variable, Absolute），用法指向
            Volume Increment / Volume Decrement / Mute 等 Consumer 用法
      - End Collection
  说明：发送时只在对应用法位置填值（如 0x00E9），其余填 0；发送完「松手」
        可再发一次 0x0000，保证系统音量不会卡在「持续增减」。

4.3 报告 ID 与发送通道
  - bt_hids 用「输入报告索引 + Report ID」区分键盘与消费报告；
  - 两个输入报告各自对应一个 GATT 特征（带 Notify），主机需先「使能通知」
    才能收到；发送前用 bt_hids 提供的连接就绪状态判断，未就绪则丢弃或入队。

----------------------------------------------------------------
五、按键 → 键盘报告
----------------------------------------------------------------
5.1 INPUT_KEY_* 到 HID 用法的翻译表（核心）
  应用层收到的是 Linux input-event-codes.h 里的 INPUT_KEY_*，必须翻译成
  HID Usage Page 0x07 的用法 ID（两者编号不同）。本键盘涉及：

  | INPUT_KEY_*        | NumLock 开（数字层）HID | NumLock 关（导航层）HID |
  |--------------------|--------------------------|--------------------------|
  | MUTE               | （不走键盘报告，见 6.3） | （不走键盘报告）         |
  | NUMLOCK            | 0x53                     | 0x53（同）               |
  | KPSLASH            | 0x54                     | 0x54                     |
  | KPASTERISK         | 0x55                     | 0x55                     |
  | KPMINUS            | 0x56                     | 0x56                     |
  | KP7                | 0x5F                     | 0x4B (Home)              |
  | KP8                | 0x60                     | 0x52 (Up)                |
  | KP9                | 0x61                     | 0x4C (PageUp)            |
  | KP4                | 0x5C                     | 0x50 (Left)              |
  | KP5                | 0x5D                     | 0x5D                     |
  | KP6                | 0x5E                     | 0x4F (Right)             |
  | KPPLUS             | 0x57                     | 0x57                     |
  | KP1                | 0x59                     | 0x4D (End)               |
  | KP2                | 0x5A                     | 0x51 (Down)              |
  | KP3                | 0x5B                     | 0x4E (PageDown)          |
  | KP0                | 0x62                     | 0x49 (Insert)            |
  | KPDOT              | 0x63                     | 0x4A (Delete)            |
  | KPENTER            | 0x58                     | 0x58                     |

  说明：
  - 本表即 矩阵按键.txt 6.3 所述的「NumLock 双功能层」落地处：keymap 设备树
    里只放数字层（INPUT_KEY_KP*），导航层（Home/Up/...）由本翻译表在 NumLock
    关闭时切换。
  - 修饰键（Ctrl/Shift/Alt/GUI）若后续有对应物理键，需把对应 INPUT_KEY_*
    映射到修饰键位图的 bit（0xE0~0xE7），不在本表内。
  - 翻译表建议放在 hid 层一个静态数组里（key_id/INPUT_KEY → HID 用法），
    改键位只改这张表，不动驱动与协议栈代码。

5.2 报告组包与发送
  1) 收到「按下」事件：在「当前按下集合」中加入该键的 HID 用法；
     收到「松开」事件：从集合中移除。
  2) 每帧把集合里最多 6 个用法填入 Byte2~7，修饰键位图填入 Byte0。
  3) 调用 bt_hids_inp_rep_send() 发送 Report ID=1。
  4) 超过 6 键时（本键盘基本不会出现），可按 6KRO 规则丢弃最早或报「卷动溢出」
     用法 0x01；本键盘规模可简单取最近 6 个。
  5) 发送失败（未连接/未使能通知）：本方案选择「丢弃」，并在连接建立后
     发送一次全键释放，避免主机残留；如需更好体验可改为「环形缓冲若干键」。

5.3 NumLock 状态来源（见第九节）
  - 初始默认开启（多数小键盘默认 NumLock on）；
  - 收到主机 HID Output Report（LED 页）里的 Num Lock 位 → 更新本地状态；
  - 本地 NumLock 键被按下/松开时，按翻译表同时维护逻辑大小写，并照样发
    键盘报告（主机自会处理 NumLock 切换的视觉态）。

----------------------------------------------------------------
六、旋钮 → 系统音量（Consumer Report）
----------------------------------------------------------------
6.1 旋转映射
  依据 旋钮编码器.txt：knob 模块每累计 1 格（±4 步）回调一次，给出方向
  KB_KNOB_CW / KB_KNOB_CCW。ble_hid 订阅该回调：
      - CW  （顺时针）→ Consumer Volume Increment（0xE9）
      - CCW （逆时针）→ Consumer Volume Decrement（0xEA）
  发送流程：
      1) 组 Consumer Report（Report ID=2）填 0x00E9 / 0x00EA；
      2) bt_hids_inp_rep_send() 发送；
      3) 发送一个「松手帧」填 0x0000，使系统音量在单格内只增减一次，
         不会因通知滞留而持续变化。

6.2 旋转加速（可选增强）
  - 旋钮编码器.txt 提到「连续快速旋转按步进倍率放大」；
  - 实现上：一次回调发一个音量步即可，系统音量本身有重复加速；
    或连续多格时每个格发一次，自然形成连续增减。

6.3 编码器按键 → 静音
  - 编码器自带按键接在 ROW0/COL3，keymap 映射为 INPUT_KEY_MUTE；
  - 该键【不走键盘报告】，ble_hid 在翻译阶段识别 INPUT_KEY_MUTE，
    改为发送 Consumer Mute（0xE2）：
      组 Consumer Report 填 0x00E2 → 发送 → 再发 0x0000（松手帧）。
  - 屏幕侧同步显示静音图标（由 display 模块订阅同一事件，不在本方案范围）。

----------------------------------------------------------------
七、BLE 连接 / 配对 / 重连
----------------------------------------------------------------
7.1 启动与广播
  - 板卡上电即初始化蓝牙协议栈（BT_Enable）；
  - 当 kb_mode_get()==KB_MODE_BLE 时启动可连接广播（Connectable
    Undirected Advertising），广播数据含设备名与「HID 服务」UUID，
    使电脑能搜到并识别为键盘；
  - 设备名建议在 prj.conf 配置（如 "kb-ble"），Appearance 设为
    HID Keyboard（0x03C1）。

7.2 配对与安全
  - 必须配对：HID 主机要求链路加密；
  - 采用 Just Works 配对 + Bonding：
      CONFIG_BT_SMP=y  CONFIG_BT_BONDING=y
      配对方式由协议栈默认（无键盘/无显示 → Just Works）；
  - 启用 Bonding 后把配对信息写入 Flash（见 7.4），下次免配对直连；
  - 若担心误操作配对，可加「长按组合键才进入可配对/清除绑定」逻辑（扩展项）。

7.3 连接事件与重连
  - 连接建立：bt_hids_connected() 标记连接就绪，开始允许发送报告；
  - 断线：bt_hids_disconnected()，清「按下集合」并停止发送；
  - 重连：Bonding 信息在 Flash，电脑会在范围内自动重连；设备侧保持广播
    （或断线后自动重启广播）即可；可设置首选连接参数（连接间隔、从机延迟、
    监督超时）以平衡响应与功耗（见第十节）。

7.4 配置持久化（Bonding）
  - 启用 settings 子系统：CONFIG_SETTINGS=y、CONFIG_BT_SETTINGS=y；
  - 配对/绑定信息由蓝牙子系统自动存 NVS，无需业务代码干预；
  - 注意：与模式切换.txt 10.4 的结论一致——「工作模式」本身不持久化
    （由物理开关决定），但蓝牙绑定信息应持久化以便重连。

----------------------------------------------------------------
八、模式切换接入（与 模式切换.txt 对接）
----------------------------------------------------------------
8.1 门控逻辑
  - ble_hid 在初始化时调用 kb_mode_register_cb() 订阅模式变化；
  - 模式回调里：
      prev/now == KB_MODE_BLE 进入：
          ○ 启动 BLE 广播（若尚未启动）；
          ○ 标记「BLE 通道激活」，按键/旋钮事件开始走 BLE 报告；
      now 离开 KB_MODE_BLE：
          ○ 先发送一次「全键释放」（Report ID=1 全 0），避免主机卡键；
          ○ （可选）停止广播或仅保留，以省电；本方案默认停止键盘广播、
            保留配置用自定义 GATT（见 蓝牙键盘方案.txt 4.7）；
          ○ 标记「BLE 通道停用」，事件转交其他模式模块。
  - 查询侧：每次组包前用 kb_mode_get() 判断是否 BLE，非 BLE 直接 return。

8.2 与 hid_bridge 的分工
  - 推荐把「模式路由」统一放在 hid_bridge：它收所有键/旋钮事件，按
    kb_mode_get() 分发给 ble_hid（BLE）或 usb_hid（USB）或丢弃（2.4G 仅显示）；
  - ble_hid 只负责「BLE 这一路怎么发」，不关心当前是不是 BLE（由 hid_bridge
    保证只在 BLE 时调用它）；这样切换逻辑集中、不重复。

8.3 切换瞬间不卡键（关键约束）
  - 任何模式切换、断开连接、进入深度休眠前，都必须先发一次全键释放；
  - 原因：主机若残留「某键按下」状态，切回后该键会一直触发，体验严重异常。

----------------------------------------------------------------
九、NumLock 与主机 LED 同步
----------------------------------------------------------------
9.1 状态维护
  - 本地维护 bool numlock_on，默认 true；
  - 键盘报告组包时，对 5.1 表中「数字/导航」双功能键按 numlock_on 选对应 HID
    用法；
  - 修饰键逻辑键（若有）不受 NumLock 影响。

9.2 接收主机 LED 状态
  - 主机通过 HID Output Report（LED Usage Page 0x08）下发 Num Lock 位；
  - bt_hids 的 Output Report 回调里读取该位 → 更新 numlock_on；
  - 同时可把「主机 Num Lock / Caps Lock / Scroll Lock」LED 状态回显到
    本键盘的 WS2812 指示灯（由 led 模块订阅，不在本方案范围）。
  - 注意：Boot Protocol 下 Output Report 为 1 字节 LED 位图；Report Protocol
    下同样经由 HID Output Report，bt_hids 统一回调，逻辑一致。

----------------------------------------------------------------
十、低功耗与 BLE 的关系
----------------------------------------------------------------
10.1 BLE 自身低功耗机制
  - nRF52840 的 BLE 链路层在「连接事件间隙」会自动让射频与 CPU 进入低功耗，
    这部分由蓝牙控制器/协议栈管理，不依赖 Zephyr 的 CONFIG_PM 子系统；
  - 经此前调测确认：本 NCS 版本中 nRF52 的 Zephyr PM 仅支持 System Off
    （HAS_POWEROFF），不支持 SUSPEND_TO_IDLE（HAS_PM 未使能），因此
    「CPU 深度休眠」走的是蓝牙链路层睡眠 + 内核 idle（WFI），而非 PM 策略。
  - 连接间隔越大越省电、响应越慢。键盘场景建议：
      首选参数：连接间隔 ~15~30 ms（兼顾打字响应与功耗）；
      从机延迟（Slave Latency）可设 0~4，进一步降占空比；
      监督超时（Supervision Timeout）建议 >= 2 s。

10.2 不可与「深度休眠」同时发生
  - 只要保持 BLE 连接（键盘要实时上报），就【不能】进入 System Off 等
    掉电态——否则连接丢失、需重新配对；
  - 所以 BLE 模式下的「低功耗」= 连接间隙睡眠 + 关闭 RGB/屏背光
    （见 蓝牙键盘方案.txt 4.6），而非整机掉电；
  - 只有在「长时间无连接 + 无操作」时，才可考虑暂时停止广播并进入更深睡眠
    （此时已无连接，唤醒后再重新广播）。

10.3 与既有低功耗/保活逻辑兼容
  - IP5306 保活心跳（保持 SYS_POWER 不掉电）在 BLE 模式下仍需运行，
    与蓝牙链路层睡眠互不冲突；
  - 矩阵 ROW 中断唤醒（任意键唤醒）依旧有效：按键按下 → 矩阵中断 →
    扫描线程唤醒 → 组包发送，符合 矩阵按键.txt 的低功耗唤醒路径。

    # ---- 蓝牙主机协议栈 ----
    CONFIG_BT=y
    CONFIG_BT_PERIPHERAL=y
    CONFIG_BT_DEVICE_NAME="kb-ble"          # 电脑搜索到的名字
    CONFIG_BT_DEVICE_APPEARANCE=0x03C1      # HID Keyboard
    # ---- 安全 / 绑定 ----
    CONFIG_BT_SMP=y
    CONFIG_BT_BONDING=y

    # ---- 服务 ----
    CONFIG_BT_HIDS=y                        # HID over GATT 服务
    CONFIG_BT_GATT_DIS=y                    # Device Information Service
    CONFIG_BT_BAS=y                         # Battery Service（电量，可选）
    # ---- 绑定信息持久化 ----
    CONFIG_SETTINGS=y
    CONFIG_BT_SETTINGS=y
    # ---- 日志/调试（沿用矩阵按键.txt 的 RTT 习惯） ----
    CONFIG_BT_LOG=y                         # 或 LOG_LEVEL 调低以省 Flash

11.2 设备树
  - BLE/bt_hids 的报告描述符与参数主要在 C 初始化结构体里给出（本方案不贴代码）；
  - 硬件侧无需新增 dts 节点（射频为片上，不占 GPIO）；
  - 仅确保板级已使能：&flash 的 settings 分区（NVS/settings 用，沿用 SDK 默认）、
    &bt 默认开启即可。

11.3 与既有 prj.conf 的关系
  - 矩阵、旋钮、模式、LED、RTT/shell 等既有 CONFIG_ 全部保留；
  - 本草案仅「追加」BLE 相关项，不改动原有输入/显示/电源配置。

12.3 验收标准
  - B01~B04、B06、B08、B11、B12、B14 必须全绿，才允许进入整机联调；
  - B07（NumLock 同步）与 B10（静音）为关键体验项，强烈建议一并验收；
  - 低功耗目标：BLE 已连接空闲电流显著低于 Active，具体数值以 PPK2 实测
    与连接间隔标定（见 10.1）。

十三、风险与注意事项
----------------------------------------------------------------
1. 报告容量限制：标准键盘报文只有 6 个键值位（6KRO）。本键盘 17 键的规模
   不会触发，但设计翻译/组包时要按「最多 6 个」处理，避免越界。
2. NumLock 双层必须在 hid 层做：keymap 设备树只含数字层，导航层靠本地
   NumLock 状态切换（见 5.1/9.1），否则导航键永远发不出。
3. 发送时机：未连接或主机未使能通知时 bt_hids_inp_rep_send 会失败，必须
   丢弃或入队，否则报错或卡死；连接建立后再补一次全键释放。
4. Consumer 报告要发「松手帧」(0x0000)：否则系统音量可能持续增减不停。
5. 模式切换/断连/休眠前务必全键释放（见 8.3），这是 HID 设备最常见体验坑。
6. BLE 与深度休眠互斥（见 10.2）：保持连接期间不能进 System Off，低功耗
   只能靠连接间隙睡眠 + 关 RGB/屏。
7. 本 NCS 版本 nRF52 不支持 Zephyr PM 的 SUSPEND_TO_IDLE（HAS_PM 未开），
   不要尝试用 CONFIG_PM 做蓝牙态的深度休眠，应依赖链路层自身睡眠。
8. Bonding 占用 Flash settings 分区，需确保板级已分配（SDK 默认具备）。
9. 广播功耗：持续广播较费电；未连接时若需极限省电，可间断广播或超时后
   停广播（此时无法被搜到，需按键唤醒再广播）——属低功耗增强项。
10. 与 USB 模式并存时（同为主控），供电与时钟由系统统一，键盘报告去重
    由 hid_bridge 按模式保证，不会双发。
