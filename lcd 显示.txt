LCD 屏幕显示实现方案（ST7789V / 320x172 / SPI）
================================================================
文档日期：2026-09-08
关联文档：项目记事本.txt（【6】屏幕 / 【10】待确认）、模式切换.txt、
          电源管理.txt、电池电压测量.txt、旋钮编码器.txt、按键led.txt
本方案只做设计，不含代码；配套代码将在确认后按本方案实现。

----------------------------------------------------------------
0. 需求一句话
----------------------------------------------------------------
ST7789V（宽 320 x 高 172，SPI 只写）上显示三行黑色背景界面：
  第一行：左=三模图标[USB][2.4G][BLE]（当前档白底红字，其余黑底白字）
          右=电池电量指示（电量百分比条按档位变色 + 充电/放电电池图标）
  第二行：居中大字时间 yyyy-MM-dd HH:mm:ss（当前为软件时钟，预留上位机同步接口）
  第三行：屏幕亮度调节滑动条（白底，左端按亮度百分比填充绿色）
交互：按住 NumLock 键期间，旋钮编码器左右旋转调节亮度。
驱动时钟源：暂以系统 uptime 为节拍（掉电不保存），预留同步接口。

1. 已核实的现状与前置事实
----------------------------------------------------------------
1.1 主控与外设占用（NCS v3.2.3 / Zephyr 4.2.99 / nRF52840）
  - 屏无 MISO，纯写 SPI；DTS 不能配 miso。
  - SDA 实为 MOSI(P0.28)、SCL 实为 SCK(P1.13)，命名反直觉，勿写反。
  - spi2 已被 WS2812 灯带独占（MOSI=P0.20，哑 SCK=P1.10）→ 屏幕必须另选实例。
  - nRF52840 有 spi0/spi1/spi2/spi3；spi3 最高 32MHz，本方案选 spi3。
  - 现有 GPIO 占用见 项目记事本.txt【2】；屏幕相关引脚当前均空闲：
      SCREEN_BLK=P1.11（背光，用 PWM）
      SCREEN_RES=P1.10（复位）
      SCREEN_DC =P0.03
      SCREEN_SDA=P0.28（SPI MOSI）
      SCREEN_SCL=P1.13（SPI SCK）
      SCREEN_CS =P0.02（SPI 片选）
  ⚠️ 冲突点：kb-pinctrl.dtsi 里 spi2 的“哑 SCK”暂用 P1.10，
     与 SCREEN_RES=P1.10 撞脚。必须在本次改动里把哑 SCK 迁到其它空闲脚
     （如 P0.14 / P1.08 / P1.12 任选其一，建议 P0.14），只改 dtsi，不影响 C 代码。

1.2 NCS 3.2.3 的 ST7789V 驱动栈（已确认可用，非旧式 display+spi 直挂）
  驱动链路：SPI(spi3) ← “zephyr,mipi-dbi-spi”（提供 DC/RES 电平与 SPI 时序）
                          ← “sitronix,st7789v” 显示设备（初始化/显存窗口）
  - 驱动文件：zephyr/drivers/display/display_st7789v.c
               zephyr/drivers/mipi_dbi/mipi_dbi_spi.c
  - 关键点：
      * st7789v 的 width/height/x-offset/y-offset/mdac/colmod/各 gamma 参数
        全部由设备树子节点提供（display-controller.yaml），不是硬编码。
      * 支持 width=320 的横置面板：SDK 自带盾板参考
        boards/shields/st7789v_generic/st7789v_tl019fqv01.overlay
        = 320x170 + mdac=0x60 + y-offset=35，与本项目“320x172”几乎同规格，
        可作为初始化的起点参数，上板只需微调 y-offset/mdac（见 6.2）。
      * Kconfig：ST7789V 默认 y（DT 使能即开）并 select MIPI_DBI；
        MIPI_DBI_SPI 默认 y；只需显式开 CONFIG_DISPLAY。
      * 像素格式二选一：ST7789V_RGB565（默认）或 ST7789V_BGR565；
        若上板发现红蓝互换，改 BGR565 即可。
      * mipi-dbi 节点带 reset-gpios（低有效）时驱动会自动做硬复位；
        dc-gpios 高=数据/低=命令，由驱动内部翻转。
      * CS 走 SPI 控制器的 cs-gpios（P0.02 低有效）。
      * display_write() 支持任意 (x,y,w,h) 局部窗口写，无需整帧缓冲，
        本方案即按“区域/行条带”局部刷新实现，避免 320x172x2≈110KB 的
        影子帧缓冲占用 nRF52840 宝贵的 RAM（见 4.4）。

3. 设备树 / 引脚 / Kconfig 设计
----------------------------------------------------------------
3.1 kb-pinctrl.dtsi 修改
  a) spi2 哑 SCK：P1.10 → P0.14（并同步修改顶部注释；若日后与其它外设再撞，
     此脚可再换，仅改此处）。
  b) 新增 spi3 引脚组（default + sleep）：
        SPIM_SCK  = (1, 13)   /* SCREEN_SCL=P1.13 */
        SPIM_MOSI = (0, 28)   /* SCREEN_SDA=P0.28 */
      （无 MISO：nRF SPIM 可只配 SCK+MOSI，与现有 spi2 写法一致。）
  c) 新增 pwm0 引脚组（背光，P1.11）：
        PWM_OUT0 = (1, 11)    /* SCREEN_BLK */

3.2 kb.dts 修改
  a) 使能并配置 spi3：
        &spi3 { status="okay";
                pinctrl-0/1 = <&spi3_default>/<&spi3_sleep>;
                cs-gpios = <&gpio0 2 GPIO_ACTIVE_LOW>; }   /* SCREEN_CS=P0.02 */
  b) 使能并配置背光 PWM（选 pwm0 即可，与其它外设实例无争用）：
        &pwm0 { status="okay";
                pinctrl-0 = <&pwm0_default>; /* 频率由应用按 1~10kHz 设置 */
                #pwm-cells = <3>; }
  c) 新增 mipi-dbi + st7789v 根节点（参考 tl019fqv01 overlay 结构）：
        / {
          chosen { zephyr,display = &st7789v; };   /* 取设备统一入口 */

          mipi_dbi0 {                       /* compatible "zephyr,mipi-dbi-spi" */
            compatible = "zephyr,mipi-dbi-spi";
            spi-dev = <&spi3>;
            dc-gpios    = <&gpio0 3 GPIO_ACTIVE_HIGH>;   /* SCREEN_DC=P0.03 */
            reset-gpios = <&gpio1 10 GPIO_ACTIVE_LOW>;   /* SCREEN_RES=P1.10 */
            write-only;
            #address-cells = <1>; #size-cells = <0>;

            st7789v: st7789v@0 {
              compatible = "sitronix,st7789v";
              reg = <0>;
              mipi-max-frequency = <16000000>;           /* 8~20MHz 均可 */
              width = <320>; height = <172>;
              /* 以下屏参先抄 tl019fqv01 起点值，上板按 6.2 调 x/y-offset 与 mdac */
              x-offset = <0>; y-offset = <35>;           /* 待实测微调 */
              mdac = <0x60>; colmod = <0x55>; lcm = <0x2c>;
              vcom/gctrl/vrhs/vdvs/gamma/porch/cmd2en/pwctrl1/
              pvgam/nvgam/ram/rgb … 全部沿用 tl019fqv01 参考参数；
              mipi-mode = "MIPI_DBI_MODE_SPI_4WIRE";
            };
          };
        };

3.3 prj.conf 追加
        # ---- LCD（ST7789V over SPI3 / MIPI-DBI）----
        CONFIG_DISPLAY=y
        CONFIG_PWM=y
        # CONFIG_ST7789V_BGR565=y   # 若上板红蓝反色再启用（默认 RGB565）
        # 调试期可开 CONFIG_DISPLAY_LOG_LEVEL=1~4
  说明：CONFIG_ST7789V / CONFIG_MIPI_DBI / CONFIG_MIPI_DBI_SPI 均随 DT 自动使能；
        SPI/I2C/GPIO 已在 prj.conf 打开，无需重复。

3.4 引脚核对表（改动后应满足）
  P0.02 屏CS   P0.03 屏DC   P0.28 屏MOSI   P1.13 屏SCK
  P1.10 屏RES  P1.11 背光PWM  P0.14=WS2812新哑SCK
  （任何新增引脚不得与矩阵/旋钮/ADC/I2C/灯带/0.00·0.01 晶振脚重复）

4. 软件总体设计
----------------------------------------------------------------
4.1 运行模型：一个 lcd 专用线程 + 事件唤醒 + 周期巡检
  - 线程 lcd_thread（栈 1536，优先级 ~7，与 led/mode 隔离阻塞式 SPI 刷新，
    避免拖累系统工作队列；参照 mode.c 独立工作队列的思路）。
  - 触发源（各回调只置脏标志 + k_sem_give，绝不在回调里做 SPI）：
      ① 模式变化     kb_mode_register_cb → 脏 top-left（三个图标）
      ② 电池状态变化 线程内周期读 kb_battery_get_status()（建议 1~2s），
                     与上次快照比对 charging/percent → 脏 top-right
      ③ 时间秒变化   线程内按 250ms 巡检 kb_time_get()，格式化串变化 → 脏第二行
      ④ 亮度变化     knob 回调 / shell 设置 → 写 PWM + 脏第三行
  - 无变化时线程休眠（250ms 周期轮询开销极小，I2C 电池读取 1s 一次即可）。

4.2 坐标布局（建议值，均为可调常量；上板用校准框微调）
  整屏 320x172、背景 0x0000(黑)。
  纵向三等分高度 ≈ 57px：
    第一行（状态栏） y=6..32，横向留边 8px
    第二行（时间区） y=57..113（中线 y≈85）
    第三行（亮度条） y=128..152（中线 y≈140）

  第一行 · 左侧三模块：
    块高 24、宽 50、块间距 6，从 x=8 起排 3 个；
    块内文字（USB / 2.4G / BLE，8x8 缩放到 1，居中）：
      当前模式块：白底 + 红字；其余块：黑底 + 白字 + 1px 白描边(可选)。
    模式为 UNKNOWN（换档死区）时：三块全部黑底白字，不强调任何一块。

  第一行 · 右侧电量组件（整体宽度约 104，右边缘 x=312 对齐）：
    ┌──────────────┬──────────┐
    │  百分比区     │ 电池图标 │      ← 整体白底（“电池背景为白色”）
    │  (宽~60)     │ (宽~30)  │
    └──────────────┴──────────┘
    ① 百分比区（电量条）：横条从左侧起按 percent% 填充；
       填充色 = percent≥60→绿、20≤percent<60→黄、percent<20→红；
       条底色/外框白，未填充部分保持白色（区域背景即“档位色”）；
       （若希望文字，可选在条内右侧叠 2~3 位小字百分比，白字/黑字均可。）
    ② 电池图标（放电态）：白色底上画黑色电池轮廓（主体+右端电极凸起），
       内部左侧画等级色小柱示意电量（可选）；
       充电态：同一位置切换为“闪电/插头”黑色符号（充电时若有需求
       也可整区闪动——初版不做动画）。
    数据：kb_battery_get_status() → percent / charging / full。
      - percent 由 BAT_ADC 模块给出（bat_adc 已在跑，60s 一测，见电池电压测量.txt）；
        当 percent==0 且尚未采到真实值时视为“未知”，可仅画白底电池不加填充。
      - charging 来自 IP5306 REG_READ0.bit3（USB 插入充电即 1）。

  第二行 · 时间：
    字符串 yyyy-MM-dd HH:mm:ss 共 19 字符，数字与符号用 5x7 点阵缩放 3 倍
    （字形宽 15、高 21），整行宽 ≈285px，水平居中、垂直居中于本带；
    颜色白字，描黑边（即点阵 1→白，0→背景黑），实现时若嫌窄可改 2 倍率。
    字库只需子集：0-9、' '、'-'、':'、'.'、'%'、'A'、'B'、'E'、'G'、'L'、'U'
    （USB/2.4G/BLE 与时间、百分号全部覆盖），放 flash 常量数组。

  第三行 · 亮度滑动条：
    整条（如 288x18，x 居中）底色白色（外框白边、内部白底）；
    从左端按 brightness% 填充绿色（绿色条右侧边缘即为“手柄”，可不另画滑块）；
    可选在条两端或右侧以小字标“%”值。

4.3 绘制策略（无整帧缓冲的局部刷新）
  - ST7789 自带 GRAM，画面掉电才丢、平时无需不停刷新；只在脏区域变化时写。
  - 以 1~2KB 的“行条带”缓冲 + display_write(x, y+r, 宽, 1) 逐行落屏：
       fill_rect / 点阵字 / 图标都先按“每行打包成 RGB565 行缓冲”，
       每行一次窗口写。单行最长 320px=640B，1KB 缓冲足够。
  - 需要“先画底再画字”的控件，按区域逐行合成后再写，保证无撕裂/残影。
  - 整行时间每秒重绘一次（≈304x21px，16MHz SPI 下 <10ms），开销可接受。
  - 全屏首绘：lcd_init 时对整屏分块清成黑色一次即可。

4.4 为什么不做整帧影子缓冲（110KB）
  nRF52840 共 256KB RAM，BLE/系统/灯带动画已占用可观内存；
  本界面元素少、变化稀疏，逐控件局部刷新即可，无需 320x172x2≈110KB 影子帧。
  若未来要动画/多窗口，再评估 LVGL（仍需 1/10 屏行缓冲策略）或按需大缓冲，
  本方案接口（lcd_redraw(region)）已为其留好扩展位。

4.5 背光与亮度（backlight 模块）
  - P1.11 用 nRF PWM 输出方波，频率建议 1~5kHz（高于可闻且省流），
    占空比 = brightness%。nRF PWM 可任意引脚，P1.11 与其余外设无冲突。
  - 接口：backlight_init() / backlight_set_percent(0..100) / backlight_get_percent()；
    默认 60%；brightness 0 视为关屏（可留黑屏时 PWM=0，最低建议 1~5%）。
  - 亮度值建议用 settings(NVS) 持久化（现有 CONFIG_SETTINGS/NVS 已开），重启恢复。
  - 屏幕休眠/亮灭（PM_DEVICE + display blanking）后续低功耗阶段再做，本方案不做。

----------------------------------------------------------------
5. 交互：NumLock 按住 + 旋钮调亮度
----------------------------------------------------------------
5.1 事件来源
  - NumLock 键物理按下已由 keymap input 设备输出 INPUT_KEY_NUMLOCK
    （键位 (1,0)，见 kb.dts keymap）；keys.c 已用 INPUT_CALLBACK_DEFINE 订阅，
    lcd 模块用同样的方式再订阅一份即可（input 子系统允许多个消费者）。
    记录 numlock_pressed 布尔：按=1、松=0。注意：NumLock 仍是普通按键，
    其“双功能层切换/主机状态同步”逻辑在 hid_keymap 里保持不变，本模块只读状态。
  - 旋钮档事件已有 kb_knob_register_cb()（回调跑在系统工作队列）。

5.2 调节规则
  - numlock_pressed==true 时，knob 回调才把 旋转方向换算为亮度增量：
    每格 detent = ±5%（可调常量），clamp 到 0..100，
    立即 backlight_set_percent()（PWM 即时生效）+ 置脏第三行。
  - 否则旋钮行为维持现状/未来既有功能（如音量等），互不干扰；
    knob 回调内【不得】阻塞，只做状态变更 + 通知 lcd 线程。
  - 防抖：NumLock 按住期间若发生其原始“层切换”语义，属既有 HID 行为，
    不在本方案改动范围内；若担心误触，可加“按住 ≥150ms 后旋钮才有效”的
    判定延时（可选）。

----------------------------------------------------------------
6. 时钟与上位机时间同步（预留接口）
----------------------------------------------------------------
6.1 软件时钟设计（kb_time）
  - 模块保存“同步基点”：epoch 秒（time_t 语义）+ 系统启动后的运行时长。
    当前绝对时间 = 基点 + (k_uptime_get() 换算的运行秒)，由 lcd 线程每 250ms
    轮询换算成 y-m-d H:M:S（采用纯整数“days-from-civil”算法，避免依赖
    标准库对时区/线程安全的要求）。
  - 上电默认时间：2026-01-01 00:00:00（可调）；掉电即复位（无 RTC 电池，
    32.768k 晶振仅给 BLE/系统时钟用）。
  - 对外接口（本方案阶段交付）：
      kb_time_get(……)  读出当前 (年/月/日/时/分/秒)
      kb_time_sync(y,mo,d,h,mi,s)  上位机/串口/测试用的写入口
      kb_time_sync_epoch(uint32_t sec)  直接给 unix 时间戳的入口
    实现上建议把“最近一次同步”也写入 settings，重启后先回放上次时间，
    减少掉电误差；实时走 uptime，秒级刷新。

6.2 与上位机的对接位（本阶段只留口，不实现传输）
  - 现有 kb_led_host_cmd() 已定义统一帧格式（[0]=0xA5 帧头、CMD、LEN、
    PAYLOAD、XOR），未来 BLE GATT 写特征 / USB Vendor OUT 收到上位机指令后，
    只调一个“lcd 命令入口”（如 kb_lcd_host_cmd()），内部解析出时间同步帧
    再转调 kb_time_sync*。具体 CMD 号待上位机协议章节再定（预留即可）。
  - 时间格式建议：帧内携带 unix epoch(4B BE) 或年月日时分秒(6B)，二选一，
    待上位机协议定稿；当前先保证 C API + shell 可测。

7. 代码实现顺序（建议的提交切分）
----------------------------------------------------------------
  M1 设备树/引脚层（可先单独编译）：
     kb-pinctrl.dtsi（哑SCK迁移 + spi3 + pwm0）
     kb.dts（spi3、pwm0、mipi-dbi、st7789v、chosen）
     prj.conf（CONFIG_DISPLAY/PWM）
     → 编译通过；先用“满屏纯色+彩条”验证初始化与窗口/偏移（见 8）
  M2 时间模块 kb_time（纯逻辑，可用 shell 验证走秒/跳变）

9. 风险与开放项
----------------------------------------------------------------
 1.【待实测】屏参（mdac/offset/colmod 等）：tl019fqv01 只是同规格参考，
    不同批次面板可能存在差异，务必先跑第 8 节“窗口标定”。
 2. SPI3 与 MIPI-DBI 属“EXPERIMENTAL”驱动（Kconfig 标记），功能成熟但
    首次引入本工程；若遇驱动问题，保留“自写精简 SPI 初始化 + display_write”
    的降级路径（改动仅限 lcd 驱动层，不影响 UI 层）。
 3. 时间精度：uptime 依赖系统节拍与 32.768k 晶振走时，误差与 BLE 主从
    模式有关；无外部同步时每日误差量级为秒级，可接受；掉电不保持，
    依赖上位机同步（正是本次预留的接口）。
 4. 内存预算：仅新增 1~2KB 行缓冲 + 线程栈 1536B，无大缓冲风险；
    若后续 LVGL 化需重审 RAM（≤110KB 帧缓冲不可取，仍需分行策略）。
 5. 电量 percent 的“分级色”档位按需求定死 60/20 阈值；若需求是“按
    百分比填充比例着档位色”，以 4.2 中的“比例条 + 档位填充色”实现为准，
    与需求文字兼容，且比纯色块信息更完整。
