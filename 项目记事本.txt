【7】电源（已核实）
----------------------------------------------------------------
  VBUS → R29(2Ω) → IP5306(U2) VIN（充电）
  电池 VBAT → SW4(SK-22D02 拨动开关) → IP5306 BAT
  IP5306 SW → U40(1uH) → SYS_POWER(5V)（C30 220uF + C32/C38 22uF）
  SYS_POWER → U37(TPSPX3819M5-L-3-3 LDO) → 3V3（主控与数字外设）
  电量采样：VBAT → 100k/100k 分压 → Q1 MOS（由 BAT_ADC_EN 控制）→ BAT_ADC(P0.31)，C29 100nF
  灯带电源：SYS_POWER → Q4/Q2(ES3139KW P-MOS) → RGB_VCC_OUT，由 RGB_PWR_EN(P0.13) 控制
  唤醒链  ：MANUAL_WAKE → U41(SN74LVC1G123 单稳态) → IP5305T_WAKEUP → IP5306 KEY
  IP5306 为 I2C 版本，R28/R31 10k 上拉到 3V3

  【三模 ADC 换算 Bug 修复 2026-09-07】
  现象：拨动三档开关，模式永远锁在 BLE；shell `mode info` 显示 MODE≈115200mV
        （满量程仅 3.6V，明显不可能）。
  根因：src/mode/mode.c 原用手写 `adc_read()` + 手写 `adc_sequence`（仅填
        channels/buffer/resolution/oversampling），缺 `adc_sequence_init_dt()`
        的必要初始化，导致 nRF SAADC 驱动以「16 位左对齐」形式返回 raw，
        而 `adc_raw_to_millivolts()` 按「12 位右对齐」换算 → 满量程被放大
        ~32 倍（左对齐×16 + 单端半量程×2）饱和成 115200mV，`classify()`
        永远判 >=3000mV → BLE，三档切换完全失效。
  修复：改用 Zephyr 官方 adc_dt 路径（与 samples/drivers/adc/adc_dt 一致）：
        - 用 `adc_dt_spec` 描述 &adc/channel@5 通道；
        - `adc_channel_setup_dt()` / `adc_sequence_init_dt()` / `adc_read_dt()`；
        - `adc_raw_to_millivolts_dt()` 由 spec 自动取增益/参考/分辨率与 raw 对齐。
        编译通过（merged.hex 已生成）。
  验证：烧录后用 `mode info` 看 MODE 电压，三档应分别 ≈0mV(USB) / ≈1500mV(2.4G)
        / ≈3300mV(BLE) 且随拨档变化；若仍偏差，按 模式切换.txt D02/D03 标定。

  【原理图二次确认 & 修复失败 2026-09-07】
  查 _sch/page0_full.png 确认【8】电路推断正确：
    U1 = SK-13D07-4 (6脚3档) + R5/R18/R19/R20(1k) + R16/R17(100k) + C9(100nF)
    中间档（开关悬空）由 R16/R17 100k/100k 分压给出 1/2 VCC = 1.65V。
    三档电压 0V / 1.65V / 3.3V 完美匹配阈值 0/1500/3000mV —— 硬件无问题。
  之前的 adc_dt 路径修改与旧代码数学完全等价（res=12/gain=1/6/ref=adc_ref_internal
  全部相同），用户烧录后 mv 仍恒定 115200（三条心跳完全无波动），切换仍失败。
  反推 raw = mv × 4096 / (ref × 6) = 131072 = 2^17 ≈ 4096×32 异常数字，
  怀疑 nRF 驱动实际返回 16 位左对齐 raw 或与 SDK adc_raw_to_millivolts 假设不符。
  下一步：无需重烧，让用户跑当前固件的 `mode info` 三档各一次，把 raw 三个
  值发回来，再据此精确定位换算公式。

  【✅ 根因确认 & 真正修复 2026-09-07】
  心跳日志加 raw 后拿到三档实测：134823 / 132927 / 131072。
  拆解发现：raw = 131072(=0x0002_0000=2^17) + 真实12位读数！
    134823 = 131072+3751 → 3.24V = BLE 档 ✓
    132927 = 131072+1855 → 1.63V = 2.4G 档（100k/100k 分压 1.65V）✓
    131072 = 131072+0    → 0V    = USB 档 ✓
  三档电压全部正确，ADC 硬件/引脚/增益/参考全正常！
  根因：sample_mv 的采样 buffer 用了 int32_t，而 nRF SAADC 每样本是 int16_t，
  驱动只写低 2 字节，高 16 位是栈上未初始化残留值（恰好恒 2 = 0x0002），
  raw 被污染成 131072+真实值 → mv 恒 ~115200 → 永远判 BLE。
  修复：sample_mv 的 buffer 改为 int16_t（adc_read 按驱动样本宽度收数）。
  验证预期：三档 mv 应为 ≈0(USB) / ≈1630(2.4G) / ≈3240(BLE)，随拨档切换。
  心跳周期暂留 5 秒便于观察，确认切换正常后改回 30 秒。
