================================================================
模式切换（三模开关 ADC 检测）实现方案
================================================================
版本：V1.0
日期：2026-09-05
平台：nRF Connect SDK v3.2.3 / Zephyr 4.2.99 / 板卡 kb（nRF52840）
依据：原理图「三模检测」部分（SW2 / R1 / C11）、SCH_蓝牙小键盘_2026-03-28.pdf
范围：只做「模式检测与标记」这一层
      1) 用 ADC 读 MODE 引脚电压，判定当前是 USB / 2.4G / BLE
      2) 对外提供「当前模式查询 + 变化通知」的接口
      3) 【不实现】BLE / USB / 2.4G 的具体通信，只把接入点预留好
说明：本文件只给方案、配置草案与验证方法，不含实现代码

----------------------------------------------------------------
一、结论（一句话）
----------------------------------------------------------------
MODE 是三档机械开关经电阻分压产生的直流电平，用 SAADC 单端采样后按电压判档；
判档结果用一个「当前模式 + 变化回调」的模块维护，其他模块（HID/屏幕/LED）
通过回调订阅，本方案不实现任何实际通信，只把接口留出来。

为什么用 ADC 而不是 GPIO：
  MODE 是三档开关，只有 1 个引脚却要表达 3 种状态，只能用电压编码（分压），
  必须走 ADC。这也是原理图上 R1(10kΩ) + C11(100nF) 的作用：
  R1 与下分压臂构成中点电压，C11 滤除开关抖动与噪声。

----------------------------------------------------------------
二、硬件事实（方案依据）
----------------------------------------------------------------
2.1 引脚

  | 信号 | nRF GPIO | 模块脚 | 说明                          |
  |------|----------|--------|-------------------------------|
  | MODE | P0.29    | 8      | SAADC 通道 AIN5（模拟输入）   |

  核对依据（与 E73-2G4M08S1C 官方引脚表、以及你之前给的矩阵表自洽）：
      模块脚 8  = AI5 = AIN5 = P0.29   <- MODE
      模块脚 10 = AI6 = AIN6 = P0.30   <- COL3（矩阵已用，工作正常）
  两者相邻但不冲突。

2.2 检测电路（原理图「三模检测」部分）

      3V3 ── R1(10kΩ) ──┬── SW2(TSC02-TDW0EHG1，三档) ──┬── MODE → P0.29
                        │                               │
                        └─ 下分压臂 → GND               C11(100nF)
                                                          │
                                                         GND

  三档分别把 MODE 接到：
      档位 1 → GND        ≈ 0 V      → USB
      档位 2 → 分压中点   ≈ 1.5 V    → 2.4G
      档位 3 → 3V3        ≈ 3.3 V    → BLE

  ⚠️ 下分压臂的阻值在现有截图里看不清，中点标称电压需实测确认（见 3.3 与 11.2）。

2.3 与其他外设的关系

  - P0.29 目前未被矩阵 / RGB / 按键占用，可放心用作模拟输入。
  - 后续 BAT_ADC（电池电压检测）也要用 SAADC，但用【不同的通道】，
    两者共用同一个 &adc 设备、各配一个 channel 节点即可，不冲突（见 12.5）。

三、电压判档与阈值
----------------------------------------------------------------
3.1 判档规则（按你给的规格）

  | 电压范围 (mV)        | 模式   |
  |----------------------|--------|
  | V <= 500             | USB    |
  | 1300 < V <= 1650     | 2.4G   |
  | V >= 3000            | BLE    |

  注意两处【未定义区间】：
      500 < V <= 1300      未定义
      1650 < V < 3000      未定义
  这两个区间是刻意留的死区——开关换档过程中电压会扫过它们，
  必须当成「正在换档 / 状态不定」处理，绝不能就近归到相邻档位。

3.2 原始码值对照表（12 位，量程 0~3600mV）

  换算：mV = raw × 3600 / 4096 ≈ raw × 0.8789 mV

  | 阈值 / 标称        | 电压 (mV) | raw 值 |
  |--------------------|-----------|--------|
  | USB 上限           | 500       | 569    |
  | 2.4G 下限          | 1300      | 1479   |
  | 2.4G 上限          | 1650      | 1877   |
  | BLE 下限           | 3000      | 3413   |
  | —— 标称值 ——       |           |        |
  | USB 标称           | 0         | 0      |
  | 2.4G 标称（估算）  | ~1475     | ~1678  |
  | BLE 标称 (3V3)     | 3300      | 3755   |

  死区宽度（按 raw 计）：
      USB↔2.4G 之间 910 个 LSB  ≈ 800 mV
      2.4G↔BLE 之间 1536 个 LSB ≈ 1350 mV
  余量极大，不需要过采样、不需要软件滤波即可稳定判档。

3.3 【必须先做的一件事】实测三档标称电压

  2.4G 档的判档区间是 1300~1650mV，中心在 1475mV。
  如果分压臂是 10k/10k，中点正好是 1650mV —— 恰好压在区间上边界，
  电阻公差一偏就可能判不出来，这是本方案最大的隐藏风险。

  做法（见 11.2 的 M02）：
      1) 三档各用万用表量一次 MODE 对地电压，记录；
      2) 要求每档标称值落在其区间的【中心附近】，且距边界 >= 150mV；
      3) 若 2.4G 标称接近 1650mV，二选一：
         a) 换下分压臂电阻，把中点压到 ~1475mV（例如上臂 10k / 下臂 8.2k → 1.487V）；
         b) 放宽判档区间（改成 1300 < V <= 1800 之类），以实测为准。
  在确认标称值之前，不要依赖 2.4G 档能稳定识别。

四、ADC 配置（为什么这么配）
----------------------------------------------------------------
4.1 量程必须覆盖 3.3V

  BLE 档标称 3300mV，所以 ADC 量程必须 >= 3.3V。
  nRF52840 SAADC 单端输入范围是 0 ~ Vref/gain，因此：

      参考源  ：内部 0.6V（ADC_REF_INTERNAL）
      增益    ：ADC_GAIN_1_6（×1/6）
      满量程  ：0.6V ÷ (1/6) = 3.6V   ✓ 覆盖 3.3V 且留 300mV 余量

  为什么不用 VDD/4 参考：VDD 会随电池电压变化（4.2V→3.3V），
  分压出来的比例虽不受影响，但参考本身漂移会引入额外误差。
  内部 0.6V 参考与 VDD 无关，电池供电场景更稳。

4.2 其他参数

      分辨率      ：12 位（4096 级，0.879 mV/LSB，够用）
      过采样      ：0（不做）——死区余量有几百毫伏，无需平均，
                    且不做过采样能让 raw 阈值表（3.2）直接成立
      采集时间    ：10 µs（ADC_ACQ_TIME(ADC_ACQ_TIME_MICROSECONDS, 10)）
                    源阻抗约 5~10kΩ，10µs 绰绰有余
      模式        ：单端

4.3 单端模式要点（易错）

  按 Zephyr 的 dt-bindings/adc/nrf-saadc.h 说明，nRF SAADC 硬件本身只支持差分，
  「单端」是负端接 GND 模拟出来的。两种写法：

      /* 真·单端：显式的负端接 GND，驱动会把结果除以 2 */
      zephyr,input-positive = <NRF_SAADC_AIN5>;
      zephyr,input-negative = <NRF_SAADC_GND>;

      /* Zephyr 模拟单端：只写正端，负值由软件钳到 0  —— 本方案用这个 */
      zephyr,input-positive = <NRF_SAADC_AIN5>;

  本方案采用【只写正端】的写法：MODE 是 0~3.3V 的正电压，永远不会有负值，
  两种写法等价，只写正端更简洁，也不会触发驱动内部的 /2 修正。

五、设备树配置草案
----------------------------------------------------------------
放在 boards/kb/kb/kb.dts：

    #include <zephyr/dt-bindings/adc/adc.h>
    #include <zephyr/dt-bindings/adc/nrf-saadc.h>

    /*
     * 三模开关检测：MODE(P0.29) = SAADC AIN5，单端。
     * 通道节点【必须命名为 channel】，否则 Zephyr 的 ADC API 宏取不到数据
     * （adc-controller.yaml 的 child-binding 明确要求）。
     */
    &adc {
        status = "okay";
        #address-cells = <1>;
        #size-cells = <0>;

        channel@5 {
            reg = <5>;
            zephyr,input-positive = <NRF_SAADC_AIN5>; /* P0.29 —— 必须是 DT 头文件里的宏 */
            zephyr,reference = "ADC_REF_INTERNAL";    /* 内部 0.6V */
            zephyr,gain = "ADC_GAIN_1_6";             /* 满量程 3.6V，覆盖 3.3V */
            zephyr,acquisition-time = <ADC_ACQ_TIME(ADC_ACQ_TIME_MICROSECONDS, 10)>;
            zephyr,resolution = <12>;
        };
    };

⚠️ 致命细节 —— AIN 编号不能用错：

    DT 头文件 (zephyr/dt-bindings/adc/nrf-saadc.h) 里：NRF_SAADC_AIN5 = 5
    nRF HAL   (nrfx/hal/nrf_saadc.h)            里：NRF_SAADC_INPUT_AIN5 = 6

  两者差 1（HAL 里 0 表示 disconnected，AIN0 从 1 开始）。
  驱动用 DT 头文件的值，并且有 BUILD_ASSERT 保证它与 nrfx 内部编号一致，
  所以 DT 里必须用 <NRF_SAADC_AIN5>（=5）。
  【若手写 6 会读到 AIN6（P0.30，就是 COL3），现象是模式永远乱跳】

5.2 关于 io-channels 消费节点

  用 Zephyr 的 ADC_DT_SPEC_GET() 需要一个带 io-channels 的节点。
  本 SDK 没有 adc-keys 之类的现成绑定，voltage-divider 又要求 output-ohms
  （语义不符——MODE 不是测分压比，是开关选通），因此本方案【采用运行时配置】：

      - 设备树只负责 &adc 使能 + channel@5 的参数；
      - C 代码用 adc_channel_setup() / adc_read() 直接操作，通道号 5 写在一处常量里。

  这样不需要自定义 binding，也没有 DT 校验风险。若以后想把参数全部搬到 DT，
  再补一个 kb,mode-switch 的自定义 binding 即可，不改接口。

七、软件架构与数据流
----------------------------------------------------------------

  [SW2 三档开关] → 分压 → C11 滤波 → MODE(P0.29)
        │
        ▼
  [驱动] SAADC (nordic,nrf-saadc)   单次采样 -> raw -> mV
        │
        ▼
  [新增] src/mode/mode.c
        ├─ 定时采样（k_work_delayable，100ms）
        ├─ 判档（含死区处理）
        ├─ 消抖（连续 3 次同一档才确认）
        └─ 模式变化时：更新当前模式 -> 依次回调订阅者
        │
        ▼
  [后续模块，本方案只留接口]
        ├─ hid_bridge   ：决定键盘事件从 USB 还是 BLE 发出
        ├─ display_ui   ：LCD 显示当前模式（2.4G 档仅需显示，无实际功能）
        └─ power_manager：按模式调整低功耗策略

  目录（沿用 蓝牙键盘方案.txt 第五节的约定）：
      src/mode/mode.h    对外 API
      src/mode/mode.c    采样、判档、消抖、回调分发
  CMakeLists.txt 的 target_sources 追加 src/mode/mode.c。

八、核心设计：采样、判档与消抖
----------------------------------------------------------------
8.1 判档函数

      classify(mv) -> USB | 2.4G | BLE | UNDETERMINED

      mv <= 500                        -> USB
      1300 < mv && mv <= 1650          -> 2.4G
      mv >= 3000                       -> BLE
      其他                             -> UNDETERMINED   /* 死区，换档过程中 */

8.2 消抖状态机（关键）

  换档时电压会扫过死区，所以规则是：

      采样值 == 当前模式      -> 清掉候选，什么都不做
      采样值 == UNDETERMINED  -> 清掉候选（正在换档，忽略）
      采样值 == 另一个有效档  -> 候选 = 该档，计数 +1
                                计数 >= 3  -> 确认切换，更新模式，触发回调

  即：必须【连续 3 次】落在同一个有效档位才认账，中间只要出现一次死区值就清零重来。

8.3 时序参数

  | 参数               | 建议值  | 说明                                  |
  |--------------------|---------|---------------------------------------|
  | INIT_SAMPLE_MS     | 10      | 上电时的连续采样间隔                  |
  | INIT_SAMPLE_N      | 3       | 上电确认所需次数（约 30ms 出结果）    |
  | POLL_PERIOD_MS     | 100     | 稳定运行后的采样周期                  |
  | DEBOUNCE_N         | 3       | 换档确认所需连续次数（约 300ms）      |

  换档响应总时间 ≈ 300ms + 一个采样周期。人手拨动开关，这个速度完全够。
  电路本身的建立时间：R(10k) × C11(100nF) = 1ms，5τ = 5ms，远小于 300ms，不冲突。

  功耗：每秒 10 次采样，每次转换约 10µs，开销可忽略；
  配合 PM_DEVICE_RUNTIME，SAADC 在采样间隙自动挂起。

8.4 边界处理

  - 上电时若采样落在死区（开关正好拨在两档之间）：模式保持 UNKNOWN，
    继续按 100ms 轮询，直到落入有效档；上报 UNKNOWN 让上层自行决定默认值。
  - 已确认某档后，若后续读数落到死区：保持原模式不变，不切也不报。

九、对外 API 草案（本方案的重点：预留接口）
----------------------------------------------------------------
src/mode/mode.h：

    /** 工作模式。数值即优先级顺序，不要用它的整数值做业务判断。 */
    enum kb_mode {
        KB_MODE_UNKNOWN = 0,   /**< 未确定（上电死区 / 尚未采样到有效档） */
        KB_MODE_USB,           /**< USB 有线 */
        KB_MODE_24G,           /**< 2.4G（本方案只需检测并标记，无实际功能） */
        KB_MODE_BLE,           /**< 蓝牙 */
    };

    /** @brief 模式变化回调 */
    typedef void (*kb_mode_cb_t)(enum kb_mode prev, enum kb_mode now, void *user_data);

    /** @brief 初始化：配置 ADC、上电即定档、启动轮询 */
    int kb_mode_init(void);

    /** @brief 查询当前模式（非阻塞，可在任何上下文调用） */
    enum kb_mode kb_mode_get(void);

    /** @brief 订阅模式变化；同一回调只注册一次。返回 0 成功 */
    int kb_mode_register_cb(kb_mode_cb_t cb, void *user_data);

    /**
     * @brief 强制设定模式（调试 / 上位机用）
     *
     * 传入非 UNKNOWN 时覆盖硬件检测结果并停止自动判档；
     * 传入 KB_MODE_UNKNOWN 时解除覆盖，恢复由 ADC 自动检测。
     */
    int kb_mode_override(enum kb_mode mode);

    /** @brief 读一次 MODE 引脚电压(mV)与原始码值，用于标定与调试 */
    int kb_mode_read(int32_t *mv, int32_t *raw);

    /** @brief 模式名（日志用） */
    const char *kb_mode_name(enum kb_mode mode);

  设计取舍说明：
   - 用【固定大小的回调数组】（建议容量 4）而不是动态分配或单回调，
     因为后续至少有三个订阅者：HID 通道选择、LCD 显示、低功耗策略。
   - 回调在【工作队列上下文】执行，因此回调里不要做阻塞操作；
     需要重活的订阅者应自行再投递事件。
   - kb_mode_get() 只返回一个枚举，读写是单字长，无需加锁即可安全读取。

十、与后续模块的接入约定（预留，本方案不实现）
----------------------------------------------------------------
10.1 HID 通道选择（对应 蓝牙键盘方案.txt 4.3）

  订阅者拿到模式后切换输出通道。切换时必须遵守两条约定（先记下，实现时照做）：
      1) 切换瞬间【先发一次全键释放】，否则主机会认为按键卡住；
      2) 切换完成后同步刷新 LCD 模式图标。

10.2 2.4G 档的处理

  按你的说明：2.4G 不需要实现具体通信功能，【只需要在 LCD 上显示对应模式】。
  因此本档位在软件上只需：检测得到 -> 标记 -> 通知订阅者（LCD 显示）。
  若将来真要接 2.4G 收发，只需新增一个订阅者，不改本模块。

10.3 与上位机协议的关系

  上位机协议里预留 GET_STATUS 返回当前模式（对应 蓝牙键盘方案.txt 4.7）。
  本模块提供 kb_mode_get()，传输层（BLE GATT / USB Vendor）直接调用即可，
  模式模块同样不感知数据走哪个通道（与 LED 模块的 kb_led_host_cmd 同一套思路）。

10.4 是否持久化到 settings

  不建议。模式由【物理开关】决定，断电后开关位置可能已被拨动，
  把上一次的模式写进 NVS 再读出来会与实际开关位置冲突。
  通电后一律以 ADC 实测为准。

十二、风险与注意事项
----------------------------------------------------------------
12.1 【最高优先级】2.4G 档标称电压可能压在判档边界
     若分压是 10k/10k，中点 = 1650mV，正好是区间上界，公差一偏就判不出。
     必须先做 D02 实测，必要时换下分压臂电阻或放宽区间（见 3.3）。

12.2 AIN 编号不能用 HAL 的值
     DT 里必须写 <NRF_SAADC_AIN5>（值为 5）。
     若误写 6，实际会采样 AIN6 = P0.30 = COL3，而 COL3 是矩阵列驱动信号，
     现象是模式读数乱跳且与拨档无关。

12.3 死区不能就近归类
     把 800mV 归到 USB、把 2000mV 归到 2.4G 看似"合理"，但换档过程会扫过这些点，
     结果是换档途中疯狂误切换。必须严格判为 UNDETERMINED 并清零候选。

12.4 电池供电下不要用 VDD 参考
     VDD 从 4.2V 掉到 3.3V 时，VDD/4 参考会漂；内部 0.6V 参考不随 VDD 变化。
     本方案已选内部参考，若日后改动，注意这条。

12.5 与 BAT_ADC 共用 SAADC
     电池检测也要用 SAADC（BAT_ADC_EN + BAT_ADC）。约定：
       - 共用同一个 &adc 设备，各配一个 channel 节点（不同 reg）；
       - 采样时各自 adc_channel_setup() + adc_read()，不要并发；
       - 若后续两者采样频率都较高，考虑统一到一个采样任务里串行执行。

12.6 MODE 引脚与矩阵引脚相邻
     P0.29(AIN5) 与 P0.30(COL3，矩阵列驱动) 是相邻焊盘。
     回板后若发现 ADC 读数受按键扫描干扰，检查是否焊连；
     软件上可临时把采样放到无按键活动时执行再对比。

12.7 采样功耗与休眠
     运行时每 100ms 采一次，开销可忽略。
     但进入深度休眠前必须【停止轮询定时器】，否则无法入睡；
     这条留给 power_manager 阶段处理，本模块需提供停止/恢复采样的接口（待补）。
