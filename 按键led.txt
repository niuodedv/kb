================================================================
按键 LED（WS2812）实现方案
================================================================
版本：V1.0
日期：2026-09-05
平台：nRF Connect SDK v3.2.3 / Zephyr 4.2.99 / 板卡 kb（nRF52840）
依据：原理图 图1（LED 使能）、图2（按键 LED）；SCH_蓝牙小键盘_2026-03-28.pdf
范围：只做「按键 LED」这一层
      1) 按键按下 -> 对应 LED 亮；按键抬起 -> 该 LED 渐灭
      2) 默认颜色绿色，全彩可调
      3) 预留与上位机通信的接口，供后续上位机修改 LED 颜色
说明：本文件只给方案、配置草案与验证方法，不含实现代码

----------------------------------------------------------------
一、结论（一句话）
----------------------------------------------------------------
用 Zephyr 官方 led_strip 子系统 + worldsemi,ws2812-spi 驱动（SPI 方式驱动），
灯链 17 颗（EC11 旋钮键无灯），按下即亮、松手渐灭，默认绿色；
颜色/亮度/效果通过一层「与传输方式无关」的 API 暴露，
后续 BLE GATT / USB HID Vendor 通道直接对接该 API 即可，LED 模块不感知传输。

为什么用 SPI 驱动，而不是 GPIO 位bang：
 1. 本 SDK 的 drivers/led_strip 下只有 ws2812_spi / ws2812_gpio / ws2812_i2s
    三个（nrfx_pwm 版已不在主线），SPI 是 nRF52840 上唯一既可靠又不阻塞系统的选择。
 2. ws2812_gpio 用 inline 汇编位bang，发送期间【关中断】。17 颗灯约 510us 关中断，
    对最终要跑 BLE HID 的本板是灾难性（会破坏射频时序），直接排除。
 3. ws2812_spi 走 SPIM + EasyDMA：CPU 只组帧，波形由硬件+DMA 产生，
    全程不关中断，BLE 时序不受影响。
 4. 代价：WS2812 是单线协议只用到 MOSI，但 SPIM 外设必须有 SCK 引脚才会出时钟，
    所以要占用一个【空闲引脚当哑 SCK】，见 2.3。

----------------------------------------------------------------
二、硬件事实（方案依据）
----------------------------------------------------------------
2.1 引脚

  | 信号        | nRF GPIO | 方向 | 说明                            |
  |-------------|----------|------|---------------------------------|
  | RGB_DATA    | P0.20    | 输出 | WS2812 DIN，接 SPI MOSI         |
  | RGB_PWR_EN  | P0.13    | 输出 | 高电平 = 灯带供电使能（RGB_VCC）|

2.2 灯珠与数量

  - 型号 WS2812B-MINI-V3J，每键 1 颗，DIN -> DOUT 串联级联成一条链。
  - 物理按键 18 个 = 17 个机械轴 + 1 个 EC11 旋钮按键（位于 ROW0/COL3，键值 Mute）。
  - (0,3)  EC11 旋钮按键【没有 LED】；其余 17 个机械轴各有 1 颗 LED。
  - 结论：chain-length = 17。

2.3 必须额外占用一个「哑 SCK」引脚（最容易漏的一点）

  WS2812 只要 MOSI，但 SPIM 外设的 SCK 若不在 pinctrl 里分配，就不会产生时钟、
  自然也就没有 MOSI 波形。因此必须把一个空闲引脚分配给 SCK（对外不接线即可）。

  当前已占用：矩阵 10 个（ROW0~5 / COL0~3）+ P0.20 + P0.13。
  按 E73-2G4M08S1C 官方模块引脚表，空闲可选用作哑 SCK：
      P1.10（模块脚 2）、P1.11（脚 1）、P0.24（脚 35）、P1.02（脚 38）、P1.04（脚 40）
  ⚠️ 绝对不要用 P0.00 / P0.01（模块脚 11/13，是 32.768kHz 晶振 XL1/XL2）。

  本方案【暂定 哑 SCK = P1.10（模块脚 2）】。
  需你按整机引脚分配（屏幕 SPI、EC11 A/B、BAT_ADC、MODE ADC、IP5306 I2C）最终确认；
  换引脚只需改 pinctrl 一处，不影响任何 C 代码。

三、LED 链路顺序与索引映射（本方案最关键的一张表）
----------------------------------------------------------------
链路顺序按你的要求：以「行」优先（ROW0 -> ROW5），行内按列升序；
遇到空位或 EC11（无灯）则跳过，不占链路位置。

          | COL0 | COL1 | COL2 | COL3 |
  --------|------|------|------|------|
  ROW0    |  —   |  —   |  —   | 无灯 |   ← (0,3) 是 EC11 旋钮键，无 LED
  ROW1    |  0   |  1   |  2   |  3   |
  ROW2    |  4   |  5   |  6   |  —   |
  ROW3    |  7   |  8   |  9   |  10  |
  ROW4    |  11  |  12  |  13  |  —   |
  ROW5    |  14  |  15  |  —   |  16  |   ← ROW5 缺 COL2，注意跳位

  合计 4+3+4+3+3 = 17，与 2.2 的 chain-length 一致。

  展开成表（实现时写成编译期常量数组，按 key_id = row*4+col 索引）：

  | 链路号 | (行,列) | 键帽      | 备注                    |
  |--------|---------|-----------|-------------------------|
  |   0    | (1,0)   | NumLock   |                         |
  |   1    | (1,1)   | /         |                         |
  |   2    | (1,2)   | *         |                         |
  |   3    | (1,3)   | -         |                         |
  |   4    | (2,0)   | 7 / Home  |                         |
  |   5    | (2,1)   | 8 / ↑     |                         |
  |   6    | (2,2)   | 9 / PgUp  |                         |
  |   7    | (3,0)   | 4 / ←     |                         |
  |   8    | (3,1)   | 5         |                         |
  |   9    | (3,2)   | 6 / →     |                         |
  |   10   | (3,3)   | +         |                         |
  |   11   | (4,0)   | 1 / End   |                         |
  |   12   | (4,1)   | 2 / ↓     |                         |
  |   13   | (4,2)   | 3 / PgDn  |                         |
  |   14   | (5,0)   | 0 / Ins   | 键帽待实测（见 矩阵按键.txt 6.2）|
  |   15   | (5,1)   | . / Del   | 键帽待实测              |
  |   16   | (5,3)   | Enter     | 键帽待实测              |
  |  无灯  | (0,3)   | EC11/Mute | 旋钮按键，硬件上无 LED  |

  实现约定：
   - 定义 LED_NONE = 0xFF，表中无灯位置（含 6 个空位 + EC11）填 0xFF。
   - 按键模块只传 (row, col)，由 LED 模块内部查表换算链路号，
     外部永远不直接操作链路号，避免「矩阵下标 / 链路号」混用。
   - 【重要】这张表是依据「行优先」这一假设推出来的，必须用 13.2 的 L02 用例实测确认。
     若实际链路顺序不同（例如蛇形走线），只改这张表，不动任何逻辑代码。

四、驱动选型与时序参数
----------------------------------------------------------------
4.1 节点与关键属性（取值依据）

  compatible           = "worldsemi,ws2812-spi"
  spi-max-frequency    = <4000000>      4 MHz
  spi-one-frame        = <0x70>         '1' 的 8 位符号
  spi-zero-frame       = <0x40>         '0' 的 8 位符号
  bits-per-symbol      = <8>            默认值，走驱动快速路径
  color-mapping        = GRB            WS2812 的线上顺序是 G-R-B
  chain-length         = <17>
  reset-delay          = <50>           锁存/复位低电平时间（us）

  这组取值是本 SDK 内 Nordic 官方板（actinius_icarus_som_dk）在树用法，
  已量产验证，不是拍脑袋：
   - 4MHz 下每个 SPI 位 250ns。
   - one  = 0x70 = 0b01110000 -> 低 250ns + 高 750ns + 低 1.0us
   - zero = 0x40 = 0b01000000 -> 低 250ns + 高 250ns + 低 1.5us
   - 驱动自带文档给的判据：'0' 高电平 200~500ns，'1' 高电平 >=550ns（典型 700ns）。
     这里 '0' = 250ns、'1' = 750ns，正好落在窗口内。

4.2 缓冲与耗时（评估功耗/CPU 用）

  一帧 SPI 数据 = 17 颗 × 3 通道 × 8 bit × 8 bit/符号 = 3264 bit = 408 字节
  传输耗时      = 3264 / 4MHz ≈ 816 us
  加上 reset-delay 50us，一次完整刷新约 866 us

  驱动会自动分配 408 字节的静态缓冲（px_buf），无需应用层准备。

五、设备树配置草案
----------------------------------------------------------------
5.1 引脚控制（boards/kb/kb/kb-pinctrl.dtsi，目前是空的 &pinctrl {}）

    &pinctrl {
        /* WS2812：MOSI = RGB_DATA(P0.20)；SCK 为哑引脚，对外不接线 */
        spi2_default: spi2_default {
            group1 {
                psels = <NRF_PSEL(SPIM_SCK,  1, 10)>,   /* 哑 SCK，暂定 P1.10 */
                        <NRF_PSEL(SPIM_MOSI, 0, 20)>;   /* RGB_DATA -> P0.20 */
            };
        };

        spi2_sleep: spi2_sleep {
            group1 {
                psels = <NRF_PSEL(SPIM_SCK,  1, 10)>,
                        <NRF_PSEL(SPIM_MOSI, 0, 20)>;
                low-power-enable;
            };
        };
    };

5.2 灯带供电（RGB_PWR_EN -> P0.13）

  用 Zephyr 的 fixed regulator 建模这路可控电源，好处是：
   - startup-delay-us 自动处理「上电到数据有效」的等待；
   - regulator_enable/disable 带引用计数，将来低功耗模块也能安全调用。

    / {
        rgb_vcc: regulator-rgb-vcc {
            compatible = "regulator-fixed";
            regulator-name = "rgb-vcc";
            enable-gpios = <&gpio0 13 GPIO_ACTIVE_HIGH>;  /* RGB_PWR_EN */
            startup-delay-us = <1000>;
            regulator-boot-off;                            /* 上电默认断电 */
        };
    };

  若不想引入 regulator 子系统，退路是：自定义一个只带 gpios 属性的节点，
  用 GPIO_DT_SPEC_GET 直接拉高/拉低。功能等价，只是上电延时要自己 k_msleep。

5.3 SPI 实例与灯链节点（放在 kb.dts）

  本 SoC（nrf52840.dtsi）提供 spi0/spi1/spi2/spi3，全部默认 disabled：
    spi0 0x40003000 / spi1 0x40004000 / spi2 0x40023000 / spi3 0x4002f000，
    compatible 均为 "nordic,nrf-spim"，上限 8MHz（4MHz 需求完全满足）。

  【暂定用 spi2】，理由：spi3（SPIM3）性能最好，留给后续屏幕等对带宽敏感的外设；
  spi0/spi1 留给屏幕 SPI 与将来可能的其他 SPI 设备。
  ⚠️ 后续做屏幕时，屏幕 SPI 必须避开 spi2，否则冲突。

    #include <zephyr/dt-bindings/led/led.h>

    &spi2 {
        compatible = "nordic,nrf-spim";
        status = "okay";
        pinctrl-0 = <&spi2_default>;
        pinctrl-1 = <&spi2_sleep>;
        pinctrl-names = "default", "sleep";

        ws2812: ws2812@0 {
            compatible = "worldsemi,ws2812-spi";
            reg = <0>;                      /* SPI 绑定要求，实际未使用 */
            spi-max-frequency = <4000000>;
            chain-length = <17>;
            spi-one-frame  = <0x70>;
            spi-zero-frame = <0x40>;
            color-mapping = <LED_COLOR_ID_GREEN
                            LED_COLOR_ID_RED
                            LED_COLOR_ID_BLUE>;   /* WS2812 是 GRB */
            reset-delay = <50>;
        };
    };

    / {
        aliases {
            led-strip = &ws2812;
        };
    };

  关于 CS：WS2812 没有片选，节点里 reg = <0> 只是为满足 spi-device 绑定的格式要求；
  SPI 父节点不写 cs-gpios 即可（Nordic 官方板 actinius_icarus_som_dk 就是这样用的，
  驱动 SPI_DT_SPEC_INST_GET(..., 0) 不 hold CS）。

七、软件架构与数据流
----------------------------------------------------------------

  [按键]  物理按键
     │
     ▼
  [现有] gpio-kbd-matrix + input-keymap      （已实现，见 src/keys/）
     │  INPUT_ABS_X=列, INPUT_ABS_Y=行, INPUT_BTN_TOUCH=按下
     ▼
  [现有] src/keys/keys.c 的 matrix_cb()      已有 (row, col, pressed)
     │  ★ 本方案唯一的接入点：在这里调 kb_led_press/release
     ▼
  [新增] src/led/led.c
     ├─ 查表 (row,col) -> 链路号（见第三节）
     ├─ 只改状态数组 + 提交延时工作项（【非阻塞】，input 线程立刻返回）
     └─ k_work_delayable 动画工作项（系统工作队列）：
           取状态 -> 组 17 颗像素 -> led_strip_update_rgb() -> 重排下一次
     ▼
  [驱动] ws2812_spi  ->  SPIM + EasyDMA  ->  RGB_DATA(P0.20)
     ▼
  [门控] regulator_enable/disable(rgb_vcc)  ->  RGB_PWR_EN(P0.13)

  [后续] BLE GATT 写 / USB HID Vendor Report
     │
     ▼  调 kb_led_host_cmd()（第十、十一节）
  [新增] src/led/ 的颜色/亮度配置

  目录（沿用 蓝牙键盘方案.txt 第五节的约定）：
    src/led/led.h      对外 API
    src/led/led.c      灯链驱动、状态机、渐灭动画、供电门控
    src/led/led_map.c  链路索引表（也可并入 led.c）
  CMakeLists.txt 的 target_sources 追加对应 .c。

  线程模型要点：
   - input 回调运行在 input 子系统线程里，绝不能在这里做 SPI 传输（866us 太慢）。
     所以 kb_led_press/release 必须只改状态 + k_work_reschedule，立即返回。
   - 真正的 SPI 刷新发生在工作队列里。
   - 状态数组被两个线程访问，需要保护：用 k_mutex 保护「状态数组 + 组帧」，
     但【SPI 传输放在解锁之后】执行，避免持锁 866us 把 input 线程卡住。

八、核心设计：状态机与渐灭动画
----------------------------------------------------------------
8.1 每颗灯的状态

    enum { LED_IDLE, LED_HELD, LED_FADE };
    struct {
        uint8_t state;    /* 上面的枚举 */
        uint8_t level;    /* 当前亮度 0~255（相对目标颜色的比例） */
    } leds[17];

8.2 行为

  按下（matrix_cb 收到 pressed=1）：
      state = LED_HELD; level = 255;    // 即亮
      （可选 PRESS_RAMP_MS 渐亮，默认 0 = 立即亮）
  抬起（pressed=0）：
      state = LED_FADE;                 // 从当前 level 开始往下减
  渐灭途中再次按下：
      取消渐灭，state = LED_HELD，level 回到 255（不会闪一下再亮）

8.3 动画节拍

       ANIM_PERIOD_MS = 16    约 60fps
       FADE_OUT_MS    = 250   松手渐灭时长（对齐 蓝牙键盘方案.txt 4.2 的 150~300ms）
       每拍衰减 step  = 255 * ANIM_PERIOD_MS / FADE_OUT_MS ≈ 16
       渐灭级数       ≈ 16 级（够平滑；想更细腻把 ANIM_PERIOD_MS 调到 10）

  每个节拍：
     1) 取 mutex
     2) 遍历 17 颗：LED_HELD 保持 255；LED_FADE 减 step，减到 0 则转 LED_IDLE
     3) 组帧：pixel = 目标颜色 × level/255 × 全局亮度/255（32 位运算防溢出）
     4) 放 mutex
     5) 若本拍有变化 -> led_strip_update_rgb()（锁外执行）
     6) 若仍有 LED 非 IDLE -> k_work_reschedule(K_MSEC(16)) 继续
        若全部 IDLE      -> 再发一次全黑帧，然后关灯带供电，停止重排（进入零功耗）

  只在「有灯在亮/在灭」时才刷新；全部熄灭后彻底停表，不产生周期性开销。

8.4 颜色与亮度

      g_color      = { 0, 255, 0 }   默认纯绿（你的要求）
      g_brightness = 255             全局亮度缩放 0~255
      输出 = g_color × level × g_brightness / (255×255)

  先只做【全局颜色】。数据结构上预留单键颜色覆盖表（per-key override），
  等上位机协议需要时再填，不改变 API 形状。

----------------------------------------------------------------
九、供电门控（RGB_PWR_EN）时序
----------------------------------------------------------------
这是本方案最容易出错的地方，必须按下面顺序来。

9.1 为什么需要门控
  WS2812 即使显示黑色也有静态电流，17 颗常电是不可接受的待机功耗
  （详见第十二节）。全灭时应切断 RGB_VCC。

9.2 上电时序（从断电到点亮）
      1) regulator_enable(rgb_vcc)    拉高 P0.13
      2) 等 startup-delay-us（1ms，已在设备树里配好，驱动自动处理）
      3) 发送第一帧数据
  ⚠️ 顺序不能反：先供电，待 VCC 稳定后再送数据，否则首帧可能丢失或乱码。

9.3 断电时序（关键：防数据线倒灌）
      1) 先发一次【全 0 帧】，让所有灯熄灭、且 MOSI 停在低电平
      2) 再 regulator_disable(rgb_vcc)  拉低 P0.13
  ⚠️ 顺序不能反。若 VDD 已经断开、而 DIN 还是高电平，
     电流会经 WS2812 输入端的 ESD 保护二极管灌进 VDD，
     造成「 phantom power（幻象供电）」：灯带靠数据线微弱供电、
     表现为关不掉、微亮、或状态错乱。先送全 0 帧把 MOSI 拉低即可避免。

十、对外 API 草案（含上位机预留接口）
----------------------------------------------------------------
src/led/led.h：

    /* 初始化：取灯链设备、供电 regulator、建工作项；失败返回负 errno */
    int kb_led_init(void);

    /* —— 按键模块调用（非阻塞，可在 input 回调里直接调） —— */
    int  kb_led_press(uint8_t row, uint8_t col);    /* 按下：查表后点亮对应灯 */
    int  kb_led_release(uint8_t row, uint8_t col);  /* 抬起：开始渐灭 */
    void kb_led_all_off(void);                      /* 立即全灭（模式切换/休眠前用） */

    /* —— 配置接口：上位机与本机共用，与传输方式无关 —— */
    int kb_led_set_color(uint8_t r, uint8_t g, uint8_t b);          /* 全局颜色 */
    int kb_led_set_color_key(uint8_t led_idx, uint8_t r, uint8_t g, uint8_t b); /* 单键，预留 */
    int kb_led_set_brightness(uint8_t level);                       /* 0~255 */
    int kb_led_set_effect(uint8_t effect);   /* 0=按下亮/松手灭 1=常灭 2=呼吸(预留) */
    int kb_led_set_fade_ms(uint16_t ms);     /* 渐灭时长 */
    int kb_led_get_config(struct kb_led_config *out);

    /* —— ★ 预留给上位机的统一入口（第十一节的帧） ——
     * 未来 BLE GATT 写回调 / USB HID Vendor Report 回调，
     * 收到数据后【只调这一个函数】，LED 模块完全不关心数据是从蓝牙还是 USB 来的。 */
    int kb_led_host_cmd(const uint8_t *frame, uint16_t len,
                        uint8_t *resp, uint16_t *resp_len);

    /* —— 持久化（可选） —— */
    int kb_led_save(void);      /* 存到 settings/NVS */
    int kb_led_load(void);      /* 启动时恢复；无记录则用默认绿色 */

十一、上位机通信协议帧（预留，供后续实现）
----------------------------------------------------------------
11.1 帧格式（与 蓝牙键盘方案.txt 4.7 的「帧头/命令号/长度/负载/校验」一致）

    偏移      字段       说明
    -------------------------------------------------------------
    0         0xA5       帧头
    1         CMD        命令号
    2         LEN        负载长度
    3 .. 2+L  PAYLOAD    负载
    3+LEN     XOR        从偏移 0 到负载末，所有字节逐字节异或

11.2 LED 相关命令（其余命令号留给时间同步、屏幕亮度等）

    CMD    名称             负载            说明
    ---------------------------------------------------------------
    0x01   SET_COLOR_ALL    R G B           设置全局颜色（你的核心需求）
    0x02   SET_COLOR_KEY    idx R G B       设置单键颜色（预留）
    0x03   SET_BRIGHTNESS   level           全局亮度 0~255
    0x04   SET_EFFECT       effect          0=默认 1=常灭 2=呼吸(预留)
    0x05   SET_FADE_MS      ms_h ms_l       渐灭时长（大端）
    0x06   SAVE             (空)            保存到 NVS
    0x07   RESET            (空)            恢复默认（绿色/255/默认效果）
    0x81   GET_CONFIG       (空)            回：R G B level effect
    0x00   ACK              (空或数据)      成功响应
    0xFF   NACK             err             失败响应 + 错误码

11.3 通道对接（后续工作，本方案只留接口）
     - BLE：自定义 GATT 服务，命令写特征 + 通知特征；
     - USB：HID Vendor Report（Usage Page 0xFF00）或 CDC-ACM；
     - 两条通道【共用同一套帧格式】，收到后都转调 kb_led_host_cmd()。
     ⚠️ 若走 BLE GATT 写，注意一次写入不要超过 MTU（默认 23 字节）；
        本帧最长 3(头)+4(负载)+1(校验)=8 字节，完全够用。

11.4 持久化（可选但建议）
     dts 里已有 storage_partition（0xf8000，32KB），可直接用
     CONFIG_SETTINGS + CONFIG_SETTINGS_NVS 存 "kb/led" 下的
     颜色/亮度/效果，实现「恢复出厂设置后默认颜色正确」这条验收项。

十二、功耗与亮度预算（重要，别等板子发烫才发现）
----------------------------------------------------------------
WS2812B 单颗每个颜色通道满亮度约 20mA：

    单颗白光 (255,255,255) ≈ 60mA
    单颗纯绿 (0,255,0)     ≈ 20mA
    17 颗全白              ≈ 1.02 A     ← 超出一般小键盘供电能力，必须避免
    17 颗全绿              ≈ 0.34 A

本方案默认行为是「只有被按下的键才亮」，正常同时亮 1~3 颗，
绿色约 20~60mA，完全可接受。

但要注意两种会翻车的场景：
 1) 上位机下发「全键盘常亮」指令（SET_EFFECT 或未来灯效）：
    17 颗全亮，电流直接上到几百 mA。
 2) 默认全局亮度拉满 255。

建议对策（写进实现）：
 - 提供 g_brightness 全局缩放，默认不要给 255（例如默认 160~180，实测再定）。
 - 在 kb_led_set_effect / set_brightness 里做「总电流上限」软限幅：
   estimated_mA = 同时点亮数 × (r+g+b)/255 × 20mA，超过阈值（例如 400mA）就按比例压低。
 - 板上 RGB_VCC 来自 IP5306 升压 + 3.3V LDO（U37 TPSPX3819M5），
   LDO 一般只有 500mA 级别，【必须实测确认】能扛住最坏情况，否则要么限流要么分批刷新。

十四、风险与注意事项
----------------------------------------------------------------
14.1 链路顺序是「假设」，必须实测（最高优先级）
    本方案按你说的「行优先」推导。若板子实际是蛇形（S 形）走线或其他顺序，
    现象是灯亮错位置。修法：只改第三节的映射表。这也是把它做成独立常量表的原因。

14.2 哑 SCK 引脚可能撞车
    暂定 P1.10。后续给屏幕 SPI、EC11、ADC 分配引脚时要复查。
    撞车表现是 SPI 初始化失败或某个外设不工作。

14.3 SPI 实例冲突
    暂定 WS2812 用 spi2。屏幕 SPI 必须用 spi0/spi1/spi3。
    若两者抢同一个实例，表现是后初始化的设备失败。

14.4 数据线倒灌（phantom power）
    不按 9.3 的顺序断电，会出现「关不掉/微亮/状态错乱」。务必先发全 0 帧。

14.5 功耗
    17 颗全亮可达数百 mA 甚至 1A（全白）。必须做全局亮度限幅，
    并实测 LDO 与电池能力（见第十二节）。

14.6 工作队列被 SPI 占用
    一次刷新约 866us，会阻塞系统工作队列。
    当前系统里其他工作项不多，先用系统工作队列；
    若后续发现影响 BLE/其他模块响应，改成专用工作队列或独立线程。

14.7 线程安全
    状态数组被 input 线程与工作队列共享，必须加锁；
    但 SPI 传输要在锁外做，否则 input 线程会被卡 866us，出现按键延迟/丢键。

14.8 时序偏差排查
    若出现错色、闪烁、末尾灯不亮：
      a) 先抓 DIN 波形核对 14.2 节的高电平宽度；
      b) 调整 spi-max-frequency（4M -> 2M 或 8M）并同步换算 one/zero frame；
      c) 调大 reset-delay（50 -> 80）；
      d) 检查 VCC 是否在发送数据前已稳定。

14.9 与低功耗的关系
    全灭时已切断 RGB_VCC。将来进 System Off 前，
    仍需调一次 kb_led_all_off() 确保灯带断电（对齐 蓝牙键盘方案.txt 4.6）。
