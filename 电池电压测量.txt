电池电压测量 —— BAT_ADC(P0.31/AIN7) 方案设计
================================================================
最后更新：2026-09-07
状态：设计方案（【尚未写代码】，按本文档实施）
引脚（用户已确认）：BAT_ADC_EN -> P0.09，BAT_ADC -> P0.31

----------------------------------------------------------------
【1】目标
----------------------------------------------------------------
  周期性测量电池电压（VBAT），换算电量百分比并对外提供查询
  （shell / 后续 BLE 电池服务 BAS / 上位机协议）。
  与现有 src/power/battery.c 对接：其 TODO(st->percent) 正是本方案要补的。

----------------------------------------------------------------
【2】硬件电路（已按 _sch/crop_modL.png 核实）
----------------------------------------------------------------
  VBAT ── R6(100kΩ) ──●── R8(100kΩ) ── Q1(NMOS, 低边) ── GND
                      │
                     C29(100nF)
                      │
                     GND
  - BAT_ADC 节点 = R6/R8 分压中点：V_BAT_ADC = VBAT × R8/(R6+R8) = VBAT/2
  - Q1 栅极 ── R9(1kΩ) ── BAT_ADC_EN(P0.09)；G-S 间 R10(100kΩ) 下拉
    ⇒ 【EN 高电平 = 采样链路导通；低/悬空 = 断开（默认断，省电）】
  - C29 100nF 滤波/保持，位于分压中点
  - VBAT 范围（锂电）：3.0V(空) ~ 4.2V(满) ⇒ V_BAT_ADC = 1.5 ~ 2.1V

----------------------------------------------------------------
【3】ADC 通道规划
----------------------------------------------------------------
  P0.31 = SAADC AIN7，与现有三模开关 MODE(P0.29/AIN5) 共用 &adc 外设。
  在 boards/kb/kb/kb.dts 的 &adc 下【新增】channel@7（与 channel@5 并存，
  两个通道各自独立配置，互不影响）：

    channel@7 {
        reg = <7>;
        zephyr,input-positive = <NRF_SAADC_AIN7>;
        zephyr,reference = "ADC_REF_INTERNAL";   /* 0.6V，不随电池漂 */
        zephyr,gain = "ADC_GAIN_1_6";            /* 满量程 3.6V */
        zephyr,acquisition-time = <ADC_ACQ_TIME(ADC_ACQ_TIME_MICROSECONDS, 40)>;
        zephyr,resolution = <12>;
    };

  - 满量程 3.6V，2.1V 最大输入占 58%，分辨率 3.6V/4095 ≈ 0.88mV/LSB
    ⇒ 电池侧分辨率 ≈ 1.76mV，远超电量百分比需要的粒度
  - ⚠️ acquisition-time 用 40µs（MODE 用 10µs）：分压网络源阻抗
    (R6∥R8 ≈ 50kΩ) 较高，采样电容充电需要更长的采样窗口

----------------------------------------------------------------
【4】SAADC 共享与并发（重要）
----------------------------------------------------------------
  SAADC 是单实例外设，mode 模块（AIN5）每 100ms 采样一次。
  Zephyr ADC API 内部有 adc_context 串行锁：battery 的 adc_read 会
  自动排队等待，两个用户并发安全，无需额外互斥。
  ⚠️ 但 battery 采样路径【不要】在系统工作队列里做长延时（LED 动画
  也跑在系统 wq）——见【6】线程模型。

----------------------------------------------------------------
【5】采样流程（一次完整测量）
----------------------------------------------------------------
  1. BAT_ADC_EN 拉高（Q1 导通，分压链路接通）
  2. 等待节点建立：时间常数 τ = (R6∥R8)×C29 = 50k × 100nF = 5ms，
     5τ ≈ 25ms 稳定 ⇒ 固定延时 30ms（Q1 关断期间 C29 残留电压也在此重建）
  3. 连续采样 8 次（软件平均；也可用 sequence 的硬件 oversampling，
     软件平均更直观），丢弃第 1 次（开关瞬间的尖峰）
  4. BAT_ADC_EN 拉低（断开链路，零静态漏电）
  5. 换算：
       V_BAT(mV) = 平均值(mV) × 2        /* R6=R8=100k，分压 1/2 */
       /* 若后续标定发现电阻有偏差，引入校准系数 K：
          V_BAT = 平均值 × (R6+R8)/R8 × K */
  6. 电量百分比映射（初版粗线性，D 阶段按实测曲线校准）：
       percent = clamp((V_BAT - 3300) / (4200 - 3300) × 100, 0, 100)
     ⚠️ 锂电真实放电曲线非线性（中段平坦、两端陡），线性只在 bring-up
        阶段用；D03 用万用表+实测电压做分段表（见【9】）

----------------------------------------------------------------
【6】线程模型
----------------------------------------------------------------
  专用轻量线程（推荐，与 mode.c 的独立 wq 思路一致）：
    - 栈 512~1024B，低优先级
    - 循环：等待触发（周期信号量/超时，默认 60s）→ 执行【5】流程
      → 更新全局状态 → 挂起等待下一轮
  - EN 拉高后的 30ms 延时用 k_msleep（在自己线程里睡，不影响系统 wq
    的 LED 动画）
  - 对外接口（bat_adc.h）：
      int  kb_bat_adc_init(void);            /* 配置通道+GPIO */
      int  kb_bat_adc_read(uint16_t *mv, uint8_t *percent);  /* 按需立即测一次 */
    - 周期循环把结果写全局快照；kb_bat_adc_read 可选做"即时触发"
  - 与 src/power/battery.c 对接：采样完成后更新其 percent 字段，
    充电/满电状态仍由 ip5306 模块提供（I2C），互不重复

----------------------------------------------------------------
【7】引脚与设备树
----------------------------------------------------------------
  1. channel@7：见【3】（加在 kb.dts 的 &adc 下）
  2. BAT_ADC_EN 用 zephyr_user 节点属性（无需新 compatible）：
       / {
           zephyr_user {
               bat-adc-en-gpios = <&gpio0 9 GPIO_ACTIVE_HIGH>;
           };
       };
     代码里 GPIO_DT_SPEC_GET(DT_PATH(zephyr_user), bat_adc_en_gpios)
  3. P0.09 默认态：输出低（Q1 关断）。GPIO_ACTIVE_HIGH 语义下写 0 = 关

----------------------------------------------------------------
【8】功耗评估
----------------------------------------------------------------
  - 分压链路导通时静态电流 = VBAT/(R6+R8) = 4.2V/200k ≈ 21µA
  - 采样周期 60s、单次导通约 35ms ⇒ 平均额外漏电 < 0.02µA
  - 关断时 Q1 漏电 + R10 上拉损耗可忽略
  - 结论：60s 周期采样对续航无可测影响；若未来要秒级刷新再评估

----------------------------------------------------------------
【9】电量-电压标定计划（D03）
----------------------------------------------------------------
  用可调电源/万用表替代电池，实测点（开路电压 → 采样 mV）：
    4.20 / 4.00 / 3.90 / 3.80 / 3.70 / 3.60 / 3.50 / 3.40 / 3.30 V
  得到 (采样mV, 真实V) 对照表，验证分压比；再按标准锂电放电曲线
  （带内阻补偿的有载电压更准，bring-up 先用开路电压）做分段映射：
    例如 [3.30,3.49,3.62,3.72,3.80,3.89,3.98,4.06,4.20] -> [0,5,10,...,100]
  ⚠️ 充电中（IP5306 charging=1）电压偏高，percent 会虚高——可在
     charging 状态下显示"充电中"而非百分比，或按充电曲线单独映射

【11】测试用例
----------------------------------------------------------------
  D01 —— 基础采样
    [ ] shell `bat info` 显示 mV，与万用表实测 VBAT×2 误差 < 1%
    [ ] 连续 5 次采样读数稳定（抖动 < ±10mV）
  D02 —— 开关时序
    [ ] EN 拉高后 30ms 内读数稳定（无上电尖峰影响）
    [ ] EN 关断后无静态漏电（万用表串入测 < 1µA）
  D03 —— 电量映射
    [ ] 可调电源扫 3.3~4.2V，percent 单调、端点正确
    [ ] 充电状态（IP5306 charging）下的显示策略生效
  D04 —— 并发与稳定性
    [ ] USB/BLE 模式切换期间 battery 采样不干扰模式检测
    [ ] 采样与 mode 轮询并发 1 小时无卡死、无采样失败日志

【12】风险与待确认
----------------------------------------------------------------
  1. 分压比按 R6=R8=100k 计算，已从原理图核实；但电阻有 1% 公差，
     D03 标定引入系数 K 修正
  2. 充电中电压虚高（见【9】），策略待定：显示"充电中"或按充电曲线
  3. C29 残留电压：Q1 长期关断后节点电荷缓慢泄放，30ms 建立时间已覆盖；
     若实测首次采样仍偏差，改为"丢弃前 2 次采样"
  4. adc_read 并发排队最坏等待一个 mode 采样周期（~ms 级），无影响
