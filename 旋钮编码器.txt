================================================================
旋钮编码器（EC11）实现方案：正反转识别 + 转动角度
================================================================
版本：V1.0
日期：2026-09-05
平台：nRF Connect SDK v3.2.3 / Zephyr 4.2.99 / 板卡 kb（nRF52840 / E73-2G4M08S1C）
依据：旋钮手册（旋钮编码器.pdf）、原理图 SW3/EC11E15244G1、现有按键/LED/模式模块代码风格
范围：只做「旋转方向 + 累计角度 + 每格(档)事件」这一层
      1) 用 A/B 两相正交信号辨识正转(CW)/反转(CCW)
      2) 累计转动角度（最小分辨率到「步 step」，对外换算到角度/档位）
      3) 对外提供「查询 + 变化回调」接口，按键(0,3)那颗 EC11 自带的开关不在此模块处理
说明：本文件只给方案、配置草案与验证方法，不含实现代码

----------------------------------------------------------------
一、结论（一句话）
----------------------------------------------------------------
EC11 是机械正交（Quadrature）编码器：A(P0.10)、B(P1.06) 两路方波相差 90°，
用「边沿中断 + 状态机查表」即可同时得到方向（±1/步）与累计步数；
30 档/15 脉冲 => 每档 12°、每步 6°（4×PPR=60 计数/圈），角度 = 步数 × 6°。

----------------------------------------------------------------
二、硬件事实（方案依据）
----------------------------------------------------------------
2.1 元件与引脚

  元件：SW3 = EC11E15244G1（机械旋转编码器，带按压开关）
  旋转两相（正交信号，本模块处理）：
      EC11A -> P0.10  (gpio0)
      EC11B -> P1.06  (gpio1)
  按压开关（不在本模块，已由矩阵处理）：
      EC11 自带的开关脚接到 ROW0/COL3 = P0.15/P0.30，
      在 keys.c 的 key_map[] 里是 {0,3,"EC11 旋钮按键(Mute)"}，
      并已在 led.c 中标记为无灯键位。本模块只管 A/B 旋转，不碰开关。

  ⚠️ 引脚来源：用户给定 A=P0.10 / B=P1.06；原理图文本中 EC11A/EC11B 网标
      确实连到 E73 模块对应脚（A 在 gpio0、B 在 gpio1）。落地前请再用万用表
      蜂鸣档核对「编码器 A 脚—P0.10」「B 脚—P1.06」连通，避免焊错。

2.2 电气特性（EC11 典型接法）

  EC11 的 A/B 是「对公共端 C 通断」的机械触点（C 通常接地），本身是开路集电极式：
  - 触点闭合时该相被拉到 C（GND）；
  - 触点断开时该相靠上拉电阻保持高电平。
  因此 nRF 侧必须提供上拉，否则引脚悬空读不到稳定电平。

  上拉方案（二选一，先确认原理图有没有外部电阻）：
  - 若原理图在 A/B 到模块之间已放过外部上拉电阻（常见 4.7k~10k 到 3V3），
    则 dts/gpio 配置为 GPIO_DISCONNECTED / 无内部上下拉；
  - 若没有外部上拉（这类小键盘常省略，依赖 MCU 内部上拉），
    则在 gpio 配置里打开 GPIO_PULL_UP。
  ★ 落地动作：目检原理图 SW3 附近 / A、B 走线上的电阻；本方案默认「无外部上拉，
    用 nRF 内部上拉」编写，若发现外部已有则把 pull 改成 none 即可。

2.3 与现有外设的关系 / 资源预算

  - A(P0.10) 在 gpio0，B(P1.06) 在 gpio1，分属两个 GPIO 端口。
  - Zephyr 的 nrfx GPIO 驱动对每个「端口」的多个中断引脚会合并到同一个
    GPIOTE PORT 事件（一个 GPIOTE 通道可监控整端口任意引脚变化），
    所以新增 A/B 两路中断【几乎不额外占用 GPIOTE 通道】——
    矩阵 6 行（5 个在 gpio0、1 个在 gpio1）也各只占 1 个 PORT 通道。
  - 因此「A/B 用双边沿中断」在 GPIOTE 资源上完全可行，无需为此改矩阵。
  - A/B 与矩阵、WS2812(SPI2)、SAADC(MODE) 互不冲突（不同外设/不同引脚）。

三、正交编码原理与计数粒度
----------------------------------------------------------------
3.1 波形

  A、B 为占空比约 50%、相位差 90° 的方波。约定（以某一种绕向为例）：
      正转 CW：  A 上升 -> B 上升 -> A 下降 -> B 下降  (00->01->11->10->00)
      反转 CCW： A 上升 -> B 下降 -> A 下降 -> B 上升  (00->10->11->01->00)
  相邻状态之间只有「1 个比特变化」，这是正交编码的灰码特性。

3.2 参数换算（关键，决定角度精度）

  给定：detents(档位) = 30，pulses(脉冲) = 15（每圈 A 相完整周期数 = PPR）。
    - 1 圈机械角 = 360°
    - 每档(detent) = 360/30 = 12°
    - 每脉冲(pulse) = 360/15 = 24° = 2 档
    - 每个 A 完整周期含 4 个正交状态，故 1 圈 = 4×PPR = 60 个「步(step)」
    - 每步(step) = 360/60 = 6°  =>  每档 = 2 步

  ★ 本模块以「步 step（每次合法单比特跳变 +1 或 -1）」为最小计数单位，
    再换算：档位 detent = step/2，角度 angle = step × 6（整数运算，避免浮点）。
    这样无论上层要「每档触发一次」还是「要平滑角度」，都能满足。

3.3 方向判定：标准查表法

  把 (A,B) 合成 2bit 状态 s = (A<<1)|B。用「旧状态+新状态」作索引查表，
  得到本次跳变的增量（+1 正转 / -1 反转 / 0 非法两比特跳变）：

      idx = (old << 2) | new
      QEM[16] = {
           0, -1, +1,  0,   // 00->00, 00->01, 00->10, 00->11
          +1,  0,  0, -1,   // 01->00, 01->01, 01->10, 01->11
          -1,  0,  0, +1,   // 10->00, 10->01, 10->10, 10->11
           0, +1, -1,  0    // 11->00, 11->01, 11->10, 11->11
      }

  要点：
  - 合法跳变只改 1 个比特 => 查表得 ±1；两比特同时翻转(0/11<->01/10) => 0，
    正好用来滤掉机械抖动造成的同时跳变，天然抗一部分 bounce。
  - 「正转/反转」的符号约定取决于 A、B 谁领先。若实测方向相反，
    只需把表整体取反，或交换 A/B 的 bit 位置，无需改其它逻辑。
    落地第一件事就是用 shell 正转一下看符号，不对就翻。

四、软件架构与线程模型
----------------------------------------------------------------
4.1 总体数据流

  [EC11 A/B] --(双边沿中断)--> gpio 回调( ISR 上下文，极短)
        │  读 A/B -> 查 QEM 表 -> 累加 step（带去抖/档聚合）
        ▼
  [src/knob/knob.c]  维护：step 累计值、方向、按档聚合
        │  每累计到 ±1 档(±2 步) -> 投递 work 项 -> 在系统工作队列里回调订阅者
        ▼
  [后续订阅者]  HID 卷动报告 / 屏幕调节 / LED 反馈（本方案只留接口）

4.2 为什么用「中断 + 查表」，而不是轮询

  - 旋转是事件型输入，中断零功耗等待，符合键盘低功耗预期；
  - 人手腕最大转速下每档间隔仍远大于几次中断抖动，中断足够跟住；
  - Zephyr PORT 机制让 A/B 中断几乎不占 GPIOTE 资源（见 2.3）。
  （若后续发现功耗/抖动问题，可退化为「高频定时器轮询采样」，算法不变。）

4.3 线程模型（与现有模块一致）

  - gpio 回调在 ISR 上下文：只做「读两引脚 + 查表 + 累加 + 必要时 k_work_submit」，
    不调用任何可能阻塞的 API。
  - 真正派发回调（可能触发 HID/屏幕/LED）放在【系统工作队列】里执行，
    与 led.c 的 anim_dwork 同队列但独立工作项，互不阻塞。
  - step 累加用原子变量（atomic_t）或无锁设计：ISR 写、查询读，
    单字长读取天然安全（参照 mode.c 里 kb_mode_get 的做法）。

----------------------------------------------------------------
五、去抖与档聚合策略（机械编码器必做）
----------------------------------------------------------------
5.1 两级处理

  (1) 非法跳变过滤：QEM 表对「两比特同时变」返回 0，直接丢弃，抗 bounce。
  (2) 按档聚合：每次合法跳变累加 step（±1）；当 |累计 step| 达到 2（=1 档）
      时，产生一次「档事件」，方向取该档的净符号，并清零 step 余数。
      —— 因为 1 档 = 2 步且同向，bounce 产生的 +1/-1 会在档内相互抵消，
         不会误触发整档，去抖效果稳健。

5.2 时间窗去抖（可选加强）

  机械 EC11 在临界点可能短促来回，建议在累加前加一个最小间隔过滤：
  若距上次「被接受的跳变」< DEBOUNCE_US（建议 500us~1ms，按实测调），
  则本次跳变暂不计入（或只更新 raw 状态、不累加）。
  注意：过快的旋转（猛拧）单档也可能 < 1ms，DEBOUNCE_US 不宜过大，
  先取 500us 上线实测，能稳定不丢步再收紧。

5.3 上电初始状态

  第一次进入回调前，先读一次 A/B 得到初始 s0 作为 old_state；
  之后所有跳变都以 old_state 为基准。上电瞬间若处于档间抖动，
  前几次非法跳变被 QEM 表滤掉即可，不影响计数。

六、设备树配置草案
----------------------------------------------------------------
在 boards/kb/kb/kb.dts 增加两个 GPIO 节点（放在 / 下，供应用取设备）：

  knob_a: knob-a-gpios {
      gpios = <&gpio0 10 (GPIO_PULL_UP | GPIO_ACTIVE_LOW)>;
      label = "EC11 A";
  };
  knob_b: knob-b-gpios {
      gpios = <&gpio1 6 (GPIO_PULL_UP | GPIO_ACTIVE_LOW)>;
      label = "EC11 B";
  };

  ⚠️ 若确认原理图已有外部上拉，把 GPIO_PULL_UP 改为 GPIO_DISCONNECTED。
  ⚠️ ACTIVE_LOW 仅表达「触点闭合=低电平」的物理语义，配合内部上拉得到
      高=断开/低=闭合；查表时按读到的值直接合成 (A<<1)|B 即可，方向符号以实测为准。

七、对外 API 草案（本方案重点：预留接口）
----------------------------------------------------------------
src/knob/knob.h：

    /** 旋转方向 */
    enum kb_knob_dir {
        KB_KNOB_NONE = 0,   /**< 无旋转 / 初始化 */
        KB_KNOB_CW,         /**< 正转（顺时针，符号以实测校准） */
        KB_KNOB_CCW,        /**< 反转（逆时针） */
    };

    /** 旋转回调：每累计 1 档触发一次
     *  @param dir   本档方向
     *  @param step  本档净步数（恒为 +2 或 -2，等价于 ±1 档）
     *  @param total 当前累计步数（带符号，跨圈连续）
     *  @param angle 当前累计角度（度，= total*6，可超过 360）
     *  @param user_data
     */
    typedef void (*kb_knob_cb_t)(enum kb_knob_dir dir, int16_t step,
                                int32_t total, int32_t angle, void *user_data);

    /** 初始化：配置 A/B 中断、上电定初态、安装回调入口 */
    int kb_knob_init(void);

    /** 查询当前累计步数（非阻塞，原子读） */
    int32_t kb_knob_get_steps(void);

    /** 查询当前累计角度（度），等同 steps*6 */
    int32_t kb_knob_get_angle(void);

    /** 清零累计（步数/角度归零，不改变硬件状态） */
    void kb_knob_reset(void);

    /** 订阅旋转事件；同一回调只注册一次。返回 0 成功 */
    int kb_knob_register_cb(kb_knob_cb_t cb, void *user_data);

    /** 方向名（日志用） */
    const char *kb_knob_dir_name(enum kb_knob_dir dir);

  设计取舍（参照 mode.c 的回调数组）：
   - 用固定大小回调数组（容量 4），不动态分配；
   - 回调在【系统工作队列】执行，回调里勿做阻塞操作，重活自行再投递；
   - get_steps/get_angle 只返回 int32，单字长读取无需加锁。

十、风险与注意事项
----------------------------------------------------------------
1. 【最高优先级】A/B 引脚务必实测连通
   EC11 三脚 A/C/B 排列易焊反；先用蜂鸣档确认 P0.10=A、P1.06=B，
   否则读到的正交相位相反，方向全程反掉（好消息：只需翻表，不影响计数）。

2. 上拉必须存在
   无上拉 => 引脚悬空，读值乱跳，计数飞掉。先确认外部上拉，没有就开内部上拉。

3. 方向符号约定
   QEM 表的 ± 是「按本方案波形约定」推导的，实际以 K02 实测校准为准；
   若反了，整体取反或交换 A/B 的 bit 位即可，不牵动其它逻辑。

4. 去抖参数勿过大
   DEBOUNCE_US 过大会在「猛拧」时丢步；先 500us 实测，稳定后再收紧。

5. 与模式检测一样避免阻塞
   中断里只累加、不阻塞；派发走系统工作队列，与 LED 动画工作项互不拖累
   （参照此前「背光+模式一起死」的隔离思路，各自独立）。

6. 角度溢出
   int32 步数上限约 ±3.5e7 步（≈ ±2e6 圈），普通使用不会溢出；
   若要做「0~360 循环角度」，由上层对 360 取模，本模块保留连续值。

7. 按压开关不在此模块
   EC11 自带开关已在矩阵 (0,3) 处理（Mute 键），本模块只认旋转，避免重复。
