电源管理（IP5306-I2C）实现方案
================================
版本：V0.1（仅方案，不含代码）
适用范围：nRF52840 + Zephyr(NCS 3.2.3) + IP5306-I2C 单键小键盘
依据：
  - 原理图 SCH_蓝牙小键盘_2026-03-28.pdf（第 1 页主图 + 项目记事本【7】电源）
  - IP5306-I2C 芯片手册 V1.2（特性/引脚）+ V1.21（寄存器文档）
  - 引脚分配已核实来源：项目记事本.txt【2】主控与引脚分配、【7】电源

------------------------------------------------
一、背景与目标
------------------------------------------------
1. 芯片：IP5306-I2C（英集芯，eSOP8，已定制 I2C 版本，非标准品）。
   职责：USB(VIN) 充电 + 锂电池(BAT) 升压 5V(SYS_POWER) + 电量 LED 指示。
2. 关键硬件链路（与 MCU 相关部分）：
   - 电池 VBAT → SW4 拨动开关 → IP5306 BAT
   - IP5306 SW → 1uH → SYS_POWER(5V)
   - SYS_POWER → TPSPX3819 LDO → 3V3 → nRF52840 与数字外设
   ⇒ SYS_POWER 由 IP5306 升压提供；一旦 IP5306 进待机关 boost，3V3 掉电、MCU 直接断电。
3. 待机机制（手册 P5 电气特性 + P8 按键方式）：
   - 负载电流持续 < 45mA 达 TloadD（默认 32s）后，IP5306 自动进待机，boost 关闭。
   - 待机静态电流 < 100µA。
   - 本机空闲时（屏/灯关闭、MCU 浅睡）SYS_POWER 侧负载很可能 < 45mA，
     若不干预，约 32s 后整机断电。
4. 目标需求：
   (A) MCU 工作期间，每隔 10s 向 IP5306 发送一个保活脉冲，阻止其进待机；
   (B) 预留电池状态接口（充放电状态、是否充满），供后续 LCD 显示。

------------------------------------------------
二、硬件连接（已核实）
------------------------------------------------
| 网络               | MCU 引脚   | IP5306 侧(经板上走线)        | 说明                      |
|--------------------|------------|------------------------------|---------------------------|
| IP5305T_WAKEUP     | P0.22      | KEY(引脚5)                   | 保活脉冲 / 手动唤醒共用    |
| IP5305T_I2C_SCK    | P0.24      | I2C SCL                      | R28 10k 上拉到 3V3        |
| IP5305T_I2C_SDA    | P1.00      | I2C SDA                      | R31 10k 上拉到 3V3        |
| (参考)MANUAL_WAKE   | —(按键)    | → U41 单稳态 → IP5305T_WAKEUP| 手动唤醒，已硬件整形       |
| (参考)VIN          | —          | VIN(引脚1) ← VBUS(R29 2Ω)    | USB 充电输入              |
| (参考)BAT          | —          | BAT(引脚6) ← 电池 SW4         | 升压输入                  |
| (参考)SYS_POWER    | —          | VOUT(引脚8)                  | 5V 主电源                 |

引脚占用核对（来自项目记事本【2】引脚表）：
  P1.00 仅作 IP5305T_I2C_SDA，P0.24 仅作 IP5305T_I2C_SCK，
  P0.22 仅作 IP5305T_WAKEUP —— 三个脚均未被矩阵/屏幕/SPI/旋钮占用，可安全分配。

------------------------------------------------
三、IP5306 I2C 寄存器要点（手册 V1.21 第 12~19 页）
------------------------------------------------
1. 总线参数
   - 从机地址：7-bit 0x75（8-bit 写 0xEA / 读 0xEB），Zephyr 用 7-bit。
   - 速率：400 Kbps；8 位寄存器地址 + 8 位数据，MSB first。
   - 读时序：Start → 0xEA → reg_addr → Restart → 0xEB → data
     （master 读最后一字节后必须发 NACK 结束，Zephyr i2c_write_read 自动处理）。
   - 写时序：Start → 0xEA → reg_addr → data → Stop。
2. 关键寄存器
   SYS_CTL0   0x00  R/W
     bit5  Boost enable(1使能/0关闭；关闭后需双击脉冲才关机休眠)
     bit4  Charger enable
     bit1  BOOST 输出常开功能(1=常开，永不轻载关机)【保活替代方案用】
     bit0  按键关机使能
   SYS_CTL2   0x02  R/W
     bit3:2 轻载关机时间 11:64S / 10:16S / 01:32S / 00:8S（默认档需实测）
   REG_READ0  0x70  R
     bit3  charge_en  1=充电中 / 0=放电        ← 充放电状态
   REG_READ1  0x71  R
     bit3  充满标志   1=已充满 / 0=还在充电     ← 是否充满
   REG_READ2  0x72  R
     bit2  轻载标志   1=轻负载 / 0=重负载
   （REG_READ3 实际偏移 0x77，为 KEY 短/长/双击标志，本方案暂不需要）
3. 重要约束（手册明确警告）
   - 对寄存器的操作必须“读→改→写”，只改目标 bit，Reserved 位绝对不能动。
   - IP5306 内部没有电压/电流信息，电量百分比必须靠外部带 ADC 的 MCU 测量
     （本板已有 BAT_ADC 分压 + BAT_ADC_EN，见项目记事本【7】）。

------------------------------------------------
四、方案设计
------------------------------------------------
4.1 防待机：10s 保活脉冲（需求 A，必做）
   机制：
   - MCU 用 P0.22 向 IP5306 KEY 发一个“短按”脉冲。
     手册 P8：按键 30ms<时长<2s 为短按 → 打开升压输出与电量灯；
     1s 内连续两次短按 = 关闭升压。因此保活必须是“单次脉冲、间隔 >> 1s”。
   - 周期 10s（远小于默认 32s 轻载关机时间，留足余量；即使出厂设为 8s 也安全）。
   - 脉宽建议 50~100ms（落在 30ms~2s 窗口内）。
   极性（待确认，见第七节）：
   - KEY 通常低有效（内部上拉，按下=拉低）。若如此，保活=把 P0.22 拉低 ~100ms 后释放。
   - 最终以示波器/实测确认有效电平；软件预留“有效电平”可配置。
   生命周期：
   - 保活定时器在 MCU 初始化后启动，仅“工作态/空闲浅睡”运行。
   - 进入 System Off（整机断电）前停止定时器，让 IP5306 自然休眠、切断 3V3，
     实现真正关机；后续由 MANUAL_WAKE(R41) 或 USB 插入重新唤醒升压。
   冲突规避：
   - P0.22 同时被手动唤醒链(U41 单稳态)驱动；MCU 仅发 100ms 短脉冲、频率低，
     与人工按键几乎不冲突，可直接推挽输出脉冲。

4.2 电池状态接口（需求 B，预留给 LCD）
   暴露统一结构体与取值函数，LCD 模块后续直接调用：
     struct kb_battery_status {
         bool charging;   // true=充电中, false=放电
         bool full;       // true=已充满
         uint8_t percent; // 0~100，来自外部 ADC（见下）
     };
     int kb_battery_get_status(struct kb_battery_status *st);
   数据来源：
   - charging / full：I2C 读 REG_READ0(0x70).bit3、REG_READ1(0x71).bit3。
   - percent：本板 BAT_ADC（分压后经 BAT_ADC_EN 使能、MCU ADC 采样）→
     电压换算百分比（具体分压比与标定曲线见“电池电量”专项，本方案只预留接口）。
   采样节奏：
   - 充放电/充满状态：每 1~5s 读一次 I2C 即可（I2C 不宜高频）。
   - 百分比：按需（如 LCD 刷新时）触发一次 ADC 采样。

4.3 备选：BOOST 常开（简化但费电）
   - 初始化写 SYS_CTL0(0x00).bit1 = 1 → IP5306 永不轻载关机，无需 10s 脉冲。
   - 代价：待机电流升至约 3mA（vs <100µA），且无法在 System Off 时真正断电，
     严重拖累电池续航。仅在“先跑通、再优化”阶段作为临时方案，不建议最终采用。
   - 推荐：坚持 4.1 的 10s 脉冲方案。

------------------------------------------------
五、Zephyr 落地（模块划分，不含代码）
------------------------------------------------
5.1 设备树（boards/kb/kb/kb.dts）
   - 选一个空闲 I2C 控制器（i2c0 或 i2c1），配置：
       SDA = P1.00, SCL = P0.24（标准开漏 + 板载 10k 上拉）。
   - 新增 PMIC 节点（无官方 binding，自定义 compatible）：
       &i2cX {
           ip5306: power-manager@75 {
               compatible = "injoinic,ip5306";
               reg = <0x75>;
               wakeup-gpios = <&gpio0 22 (极性)>;
               status = "okay";
           };
       };
   - 确认 P1.00 / P0.24 / P0.22 未被其他节点（spi、leds、矩阵）声明占用。

5.2 驱动/模块（src/power/ 或 src/battery/）
   - ip5306.c / ip5306.h
       * i2c 设备获取 + 读写封装（read-modify-write，保护 Reserved 位）
       * ip5306_get_charge()  → REG_READ0 bit3
       * ip5306_is_full()     → REG_READ1 bit3
       * ip5306_keepalive_start() / _stop()  → 内部 k_work_delayable，10s 周期
         pulse_wakeup() 翻转 wakeup-gpios 指定极性 ~100ms
       * （可选）ip5306_set_boost_always_on(bool)
   - battery.c / battery.h
       * 聚合 I2C 状态 + ADC 百分比，实现 kb_battery_get_status()
       * 供 LCD/UI 后续调用（本方案只定义接口，不接 UI）

5.3 配置（prj.conf）
   CONFIG_I2C=y
   CONFIG_GPIO=y            （已开）
   CONFIG_LOG=y             （已开，用于调试）

5.4 启动集成（src/main.c 或电源模块 init）
   - 初始化 I2C / ip5306，启动 10s 保活定时器。
   - 保活仅在“整机需保持开机”时运行；System Off 流程里先停定时器再断电。

七、待确认清单（写代码前必核）
------------------------------------------------
1. IP5306 KEY 引脚有效极性（高有效 / 低有效）→ 决定保活脉冲电平。
   （建议：先用 P08 法实测，或查板上 KEY 上拉/下拉。）
2. 板上 IP5306 的 I2C 实际复用在哪几个脚（LED1/LED2/LED3/KEY 之一）。
   软件只需关心 MCU 侧 SDA=P1.00 / SCL=P0.24，不影响逻辑；
   但需确认原理图确实把 I2C 接到了这两脚（而非仅 LED 指示）。
3. BAT_ADC_EN / BAT_ADC 精确引脚（项目记事本标【待确认】，疑似 P0.31），
   用于百分比采样，需与矩阵/ADC 分配再核对。
4. IP5306 出厂 SYS_CTL2 轻载关机时间档位（8/16/32/64s），
   决定余量，但 10s 脉冲对任意档都安全。
5. 最终采用「10s 脉冲」还是「BOOST 常开」——建议前者（续航优先）。
6. 是否需要把“手动唤醒(U41)”也上报给 MCU（目前 U41 直接驱动 KEY，
   MCU 不需读；若后续要区分“按键开机”可再加 GPIO 输入）。

------------------------------------------------
八、风险与注意
------------------------------------------------
- 误发“1s 内两次脉冲”会被识别为双击 → 关闭 boost → 整机断电。
  保活务必单次、间隔 >> 1s（10s 满足）。
- I2C 写寄存器务必 read-modify-write，禁止整字节覆盖（会破坏 Reserved/其他功能位）。
- 保活定时器不能在 MCU 仍要工作时停；停的唯一时机是准备 System Off 整机断电。
- 板载 I2C 上拉为 10k，nRF TWIM 内部上拉可关；若波形上升沿缓，可减小上拉或降速。
- IP5306 不提供电量百分比，百分比完全依赖外部 ADC，需单独标定（不在本方案范围）。
