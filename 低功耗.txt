低功耗（两级空闲降载 / 断电停机）实现方案
===========================================
版本：V1.0（已按本方案实现：src/power/pm.c、src/mode/mode.c 等，编译通过）
适用范围：nRF52840 + Zephyr(NCS 3.2.3) + IP5306-I2C 三模数字小键盘
依据：
  - 需求（口头）：1) 持续 1 分钟无操作 → 降频 + 调低 LCD 亮度，
      按任意键 / 转旋钮 / 切模式即恢复；2) 持续 5 分钟无操作 → CPU
      进入低功耗，之后靠电源开关重启；3) 1~5 分钟内 IP5306 持续保活。
  - 既有文档：电源管理.txt（IP5306 保活/待机）、蓝牙键盘方案.txt 4.6、
    BLE通信.txt 第十章（BLE 与深度休眠互斥）、按键led.txt 9/14 节
    （LED 供电门控、System Off 前全灭）、lcd 显示.txt 4.5（背光）。
  - 实现现状：src/power/ip5306.c（10s/80ms 保活）、bat_adc（60s 采样线程）、
    src/mode/mode.c（100ms ADC 轮询 + 30s 心跳日志）、src/lcd/lcd.c
    （200ms 专用刷新线程 + 1s 电池 I2C）、src/lcd/backlight.c（PWM 反极性，
    pct 越大越亮）、src/knob/knob.c（旋转回调，系统 wq 派发）、
    src/keys/keys.c（矩阵 + keymap 双 input 订阅）、src/led（WS2812 +
    RGB_VCC 门控）。

------------------------------------------------
一、结论摘要
------------------------------------------------
1. 两级都基于「最近一次用户活动」计时：
   - 档 1 = 持续 1 分钟无活动 →「Idle 降载」：暂停非关键轮询、
     停 LCD 刷新并调低背光；按任意键/转旋钮/切模式立即全量恢复。
   - 档 2 = 持续 5 分钟无活动 →「POWER OFF」：清场后停 IP5306 保活
     → IP5306 自动进待机切断 3V3 → 整机断电；再次开机走电源开关。
2. ⚠️ 平台硬约束（先讲清，避免误解）：
   - nRF52840 CPU 主频固定 64 MHz，**没有运行时变频能力**（无 PLL 分频/
     DVFS 接口）。本方案把“降频”落地为「空闲降载」：CPU 依然 64 MHz，
     但只干“必须干”的事（保活脉冲 + 唤醒监听），其余时间停在
     WFI 睡眠，实际平均功耗大幅下降。若需求书面含义是“主频必须降到
     某一数值”，当前平台做不到，需换主控（见 8.4 风险）。
   - 本 NCS 版本 nRF52 的 Zephyr PM 只支持 System Off（HAS_POWEROFF），
     不支持 SUSPEND_TO_IDLE。档 2 的“CPU 低功耗” = CPU System Off +
     PMIC 待机断电，二者叠加才是真正微安级关机。
   - 档 2 断电（3V3 掉电）后无法用按键/旋钮唤醒——没有供电就没有软件；
     这正是“只能靠电源开关重启”的原因，与需求一致。
3. 充电/有线供电的处理（默认，可改，见第八节）：检测到 IP5306 充电
   状态时【不进任何降载档】——充电意味着有稳定电源，省电无意义且
   用户可能正插着用；拔掉（回到放电）后才重新计时。因板上无 VBUS
   检测引脚，充电状态靠 I2C 读 REG_READ0.bit3 判断。

------------------------------------------------
二、功耗现状盘点（决定省电动作优先级）
------------------------------------------------
当前空闲时的周期性开销与主功耗源（按影响从大到小）：

| # | 模块 | 现状 | 空闲时处置 |
|---|------|------|-----------|
| 1 | LCD 背光 PWM | 默认 60% 常亮，P1.11 | 档1 调低到可配置 Idle 亮度 |
| 2 | LCD 刷新线程 | 每 200ms SPI 写屏 + 每 1s I2C 读电池 | 档1 挂起该线程 |
| 3 | WS2812 灯带 | 无键时已灭 + RGB_VCC 已切（常灭即断电） | 档1/2 维持切断 |
| 4 | 矩阵/输入 | 无键时中断静默 | 保持（任意键 = 唤醒源） |
| 5 | 旋钮 GPIO | A/B 双边沿中断，静默 | 保持（旋转 = 唤醒源） |
| 6 | 模式轮询 | mode wq 每 100ms 读一次 SAADC；30s 心跳日志 | 档1 拉长到 ~1s、停心跳日志 |
| 7 | 电池采样 | bat_adc 线程每 60s 使能分压采一次 | 档1 暂停（屏幕不显示电量） |
| 8 | IP5306 保活 | 每 10s P0.22 一个 ~80ms 脉冲 | 档1 必须继续；档2 停止 |
| 9 | BLE | 已连接时按连接间隔醒来收包 | 档1 保持（见 8.3 待确认） |
| 10 | USB | 仅 USB 档使能；主机可 selective suspend | USB 档见 8.5 待确认 |

注：屏幕 ST7789 有自刷新 GRAM，停刷后画面保持不丢，恢复时全量重绘一次
即可补齐走秒。整机断电（档2）会自然清屏，无需额外“关屏/清屏”命令。

------------------------------------------------
三、状态机设计
------------------------------------------------
3.1 状态定义
  ACTIVE   —— 正常工作：全部模块全速（现状行为）。
  IDLE     —— 档1：降载省电（见 5.2 动作清单）。
  POWEROFF —— 档2：断电停机（见 6 流程）。

3.2 迁移条件（统一以「最近一次用户活动」为基准计时）
             持续无活动 1 分钟                持续无活动 5 分钟
  ACTIVE ───────────────────────► IDLE ───────────────────────► POWEROFF
     ▲                              │                               │
     │ 任意键按下 / 旋钮旋转或按下 /  │                               │
     │ 模式档位变化（任一活动）       │  (充电开始 = 回到 ACTIVE 并    │
     └──────────────────────────────┘   暂停计时；详见 4.3)          │
                                                                   ▼
                                                     电源开关 SW4 重新上电
                                                     （或 USB 插入触发充电）
                                                     → 冷启动 → ACTIVE

  - 计时基准：从「最后一次活动时刻」起算，满 1 分钟进 IDLE、满 5 分钟
    由 IDLE 升级进 POWEROFF（5 分钟是从最后一次活动起算的绝对空闲，
    不是进入 IDLE 后再等 4 分钟——按需求原文“持续 5 分钟没有操作”理解）。
  - IDLE 期间任意一次活动立即回到 ACTIVE 并重启两个计时器。

3.3 活动源（注册点，全部只做「更新时间戳 + 必要时触发恢复」这类轻动作）
  1. 任意按键（含 EC11 按压=Mute、NumLock）：挂 input 回调
     在 keymap 设备（与 keys/ble/usb 同点，收到解析后键值，按下即可）。
  2. 旋钮旋转：kb_knob_register_cb() 注册一个活动回调。
  3. 模式档位切换：kb_mode_register_cb() 注册活动回调。
  4. （可选）充电状态变化：充电轮询发现充电开始 = 活动 + 豁免（4.3）。
  依赖槽位现状：knob 回调槽当前已被 lcd/ble/usb 占 3 个、上限 4，
  本模块加入会占满 → 需把 knob.c 的 CB_SLOTS 由 4 提到 6；
  mode 回调槽被 ble/usb 占 2、上限 4，加入 1 个没问题；
  input 设备回调为链表，无容量问题。

------------------------------------------------
四、计时与豁免
------------------------------------------------
4.1 计时器：新模块 src/power/pm.c（对外 kb_pm_*）
  - 两个 k_work_delayable：idle_work（1 分钟到点进 IDLE）、off_work
    （5 分钟到点进 POWEROFF）。
  - 每次活动（3.3 任一）:记录 now，重排 idle_work=+1min、off_work=+5min；
    若当前在 IDLE → 立即执行“IDLE→ACTIVE 恢复动作”（见 5.3）。
  - 进入 IDLE 后 idle_work 不再使用，off_work 继续等满 5 分钟。

4.2 1~5 分钟窗口内的保活
  - 需求：这段时间 IP5306 必须持续保活 → 现有 10s/80ms 保活定时器
    （system wq 上的 k_work_delayable）【原样运行】，与 IDLE 不冲突：
    IDLE 只挂起 LCD 刷新线程、放缓 mode/bat_adc，不触碰系统工作队列，
    保活工作项照常每 10s 醒来发脉冲后继续睡。
  - 不要在 IDLE 期间调用 ip5306_keepalive_stop()，否则 IP5306 会在
    ≤ 默认轻载关机时间（8~64s）内自动待机、整机掉电——那等于把
    “5 分钟档”提前到了“1 分钟档”。

4.3 充电豁免（默认开启，见第八节待确认）
  - pm 模块维护自己的充电轮询：IDLE/计时期间每 ~2s 读一次
    ip5306_get_charge()（I2C 两字节读，开销极小）。
  - 充电开始 → 取消两个计时器、恢复 ACTIVE（把背光等恢复正常）后
    不再计时；充电结束（重新放电）→ 重新起 1min/5min 计时。
  - 进 POWEROFF 前再读一次，确认不在充电才执行断电。
  - 说明：无 VBUS 检测引脚，只能靠 I2C 充电位判断“是否插着电源”。

------------------------------------------------
五、档 1：IDLE 降载（持续 1 分钟无活动）
------------------------------------------------
5.1 进入条件
  自最后一次活动满 1 分钟；且当前不充电（4.3）。

5.2 进入动作（全部轻量、可逆）
  1) LCD 刷新线程挂起：新增 lcd 空闲接口（如 kb_lcd_set_idle(true)），
     线程改用 k_sem 等待而不是 200ms k_sleep 轮询；挂起期间不刷 SPI、
     不读电池 I2C，画面保持最后一帧。背光不归 lcd 管，见下。
  2) 背光调低：记下当前亮度 → kb_backlight_set_percent(IDLE_BRIGHT)，
     IDLE_BRIGHT 建议 3~5%（人眼仍可见，不至于像“黑屏故障”）；
     可配 shell。
  3) 按键灯：kb_led_all_off()（若当时正有灯亮）；RGB_VCC 门控沿用
     led 模块“全灭即切断”的既有路径。
  4) bat_adc 暂停：新增 kb_bat_adc_set_sampling(false)（线程休眠，
     恢复时再补一拍），因为 IDLE 期间屏幕不显示电量。
  5) mode 轮询放缓：新增 kb_mode_set_poll_period_ms(1000)（SAADC 唤醒
     从 100ms/次降到 1s/次），并停 30s 心跳日志（那是 debug 心跳）。
     换档检测仍有 ~1s 延迟，作为唤醒源足够。
  6) BLE/USB：不做任何断开动作（保持连接；行为与现状一致）。
  7) IP5306 保活：继续运行（4.2），不动。

5.3 恢复动作（IDLE→ACTIVE，任一活动触发）
  1) kb_lcd_set_idle(false)：恢复线程，先做一次全量重绘
     （补齐走秒/电量/时间），再恢复 200ms 常规轮询。
  2) 背光恢复到进入前亮度（模块内保存，不落盘亦可；若要跨断电保持，
     见 8.6 选项）。
  3) kb_bat_adc_set_sampling(true)。
  4) kb_mode_set_poll_period_ms(100)，恢复 30s 心跳日志。
  5) 两个计时器按当前活动时刻重新起算。
  顺序注意：先恢复再让事件照常分发，避免把“唤醒用的这次按键/旋转”吞掉
  ——按键/旋钮事件本身仍照常上报（HID 发送/LED 点亮），pm 只是加看门。

5.4 “恢复 CPU 频率”的说明
  按 1.2 节，档 1 从未改变主频：所谓“恢复”= 恢复上述轮询节奏与
  外设活动，等效满速体验。文档与日志用词统一为“退出省电 / 恢复满速”，
  避免在 RTT 里写“恢复频率”造成误读。

六、档 2：POWER OFF（持续 5 分钟无活动）
------------------------------------------------
6.1 前置守卫（任一不满足则暂缓，条件满足后重新计时）
  - 当前不充电（4.3）；
  - kb_mode_get() 非 KB_MODE_UNKNOWN（避免换档死区中断电）；
  - （待确认项，默认放行）BLE 已连接不阻止断电；断电即断链，
    冷启动后重新广播/回连（bonding 已在 NVS，不需重新配对）。

6.2 关机动作（顺序执行，任何一步失败都应中止本次断电并回 ACTIVE）
  1) 全键释放：BLE 走公共 HID 状态清空 + 补发全零键盘报告；
     USB 若枚举中同样清空——防止主机残留按键（对齐
     BLE通信.txt 8.3 / 蓝牙键盘方案.txt 4.6）。
  2) 按键灯：kb_led_all_off()；RGB_VCC 门控关闭（灯带彻底断电）。
  3) LCD：背光 kb_backlight_set_percent(0)；刷新线程挂起
     （kb_lcd_set_idle(true)）。
  4) 持久化：settings(NVS) 落盘需要保存的项（可选：上次亮度等，
     见 8.6；time 模块回放逻辑按 kb_time 现状）。
  5) 停 IP5306 保活：ip5306_keepalive_stop()（电源管理.txt 4.1 约定：
     停定时器的唯一时机 = 准备整机断电）。
  6) CPU 进入 System Off：CONFIG_POWEROFF=y + sys_poweroff()
     （Zephyr lib/os/poweroff.c 调用 nRF SoC 的 z_sys_poweroff()）。
     若未开 CONFIG_POWEROFF（代码里 #if 保护），退化为空转挂死，
     同样靠下一步 IP5306 自动待机断电兜底。
  7) IP5306 轻载自动待机：保活停止后，SYS_POWER 侧只剩 LDO 静态 +
     MCU System Off（微安级）< 45mA，IP5306 按默认轻载关机时间
     （出厂 8~64s 之一）自动关 boost → 3V3 掉电 → 整机断电。
     若想立刻断电（不等自动待机），可选备选：向 KEY 发“1s 内双脉冲”
     触发关机（ip5306_manual/电源管理有警告，见 8.7）。
  8) 重启路径（需求指定）：
     - SW4 系统电源开关：OFF→ON 重新给 IP5306 BAT 供电 → 上电升压
       → MCU 冷启动（完整重跑 main 初始化）；
     - 或插入 USB（VIN）触发充电并重新上电；
     - MANUAL_WAKE（可选电源键）同理（U41 整形后驱动 KEY）。
     冷启动后 BLE bonding/时间回放等由各模块既有逻辑处理。

6.3 断电后为什么“按键/旋钮不能唤醒”
  3V3 已被 IP5306 待机切断，MCU 无供电；需求指定用电源开关重启，
  与硬件能力一致（nRF System Off 即便保留唤醒源也无法给 3V3 上电）。

八、待确认项（实现前请用户拍板；括号内为默认值）
------------------------------------------------
8.1 “降频”的语义 →（按 1.2 落地为“空闲降载”，文档/日志不写“降频”）；
     若必须真降主频，本平台不支持，需评估换主控。

8.6 亮度/模式等是否需要跨断电保存 →（默认不新增持久化，维持现状：

九、验证清单（PPK2 + RTT，参照既有文档风格）
------------------------------------------------
9.1 电流测量（PPK2，电池供电）
  [ ] ACTIVE 平均电流（背光 60%、无键、BLE 已连）——基线
  [ ] IDLE 平均电流（背光 5%、LCD 停刷）——应显著低于基线
  [ ] POWEROFF 后整机电流——应达 IP5306 待机 <100µA + LDO 泄漏量级
      （注意测量需等 PMIC 自动待机完成，最长 ~64s）
9.2 功能验证
  [ ] 1 分钟无操作：RTT 出现“进入省电(Idle)”，背光变暗；
  [ ] 按任意键：恢复亮度 + LCD 全量重绘 + 计时器归零，键值正常上报；
  [ ] 转旋钮（含 NumLock 两种层）：恢复并执行音量/亮度功能不丢；
  [ ] 拨模式开关：恢复且模式切换正常（含 30s 心跳日志恢复）；
  [ ] IDLE 期间每 10s 仍见保活脉冲日志（或示波器 P0.22），SYS_POWER 不掉；
  [ ] 5 分钟无操作：全键释放、RGB 断、背光灭、进入 System Off，
      随后 SYS_POWER/3V3 掉电（观察 ~≤64s）；
  [ ] 断电后用 SW4 重新上电：冷启动正常、BLE 免配对重连；
  [ ] 充电豁免：充电中静置超 5 分钟 → 不休眠；拔线后重新计时 5 分钟断电；
  [ ] IDLE 期间插入充电 → 恢复 ACTIVE；
  [ ] 长稳：反复进入/退出档 1 数十次，无残影、无死机、无日志错乱。
9.3 shell 调试命令（已实现，RTT 输入）
  pm status    —— 当前状态(满速/Idle/Off)/自动/充电/背光 + 活动与各档计数
  pm idle 或 pm now —— 立即进档 1（测量用，等效 1 分钟无操作）
  pm off       —— 立即走档 2 流程（测量用，等效 5 分钟无操作）
  pm auto on|off —— 开关自动省电（标定/长测时用）

------------------------------------------------
十、风险与注意
------------------------------------------------
1. 停保活后 PMIC 自动待机依赖“SYS_POWER 侧负载 < 45mA”：断电前必须把
   背光、LCD、RGB、CPU 全部关到位；若实测仍有 >45mA 负载（如某路未切断），
   PMIC 不会待机，整机将停在 CPU System Off + PMIC 常开的 ~mA 级，
   需排查负载（8.7 双脉冲关机可作为兜底手段）。
2. 保活期间严禁 1s 内两次脉冲（会被识别为“双击关机”），IP5306 保活
   实现已有约束，pm 不得额外碰 P0.22。
3. IDLE 只挂起/放慢轮询，禁止停掉系统工作队列（保活与 knob/mode 工作项
   都跑在 system wq 或各自 wq 上）。
4. 进入 POWEROFF 的清场顺序不可颠倒：全键释放 → 灯/屏断电 → settings
   落盘 → 停保活 → System Off，任何一步失败要能回 ACTIVE 而不是“半死”。
5. 档 1 期间 RTT 日志本身会周期性唤醒 CPU（SEGGER 轮询/调试通道），
   实测电流时用无日志版本或降低日志级别（此为测量误差来源，非固件缺陷）。
6. 系统时钟：档 1/2 计时用 k_uptime（LFCLK/RTC 驱动，已在跑），不依赖
   HFXO，睡眠期间走时准确。
7. 若后续加“任意键唤醒 System Off”（nRF 支持保留唤醒源），需重新评估
   供电方案（当前 3V3 断电后按键无法上电），本方案不采用。
8. 目标数值（估算，最终以 PPK2 为准）：档 1 收益主要来自背光调暗 +
   LCD 停刷（LCD/背光通常是最大单项）；档 2 应达到整机待机（µA 级）目标。
